# 02 — 出库 / 销售模块

> 状态：详细需求分析准备中
> 文档性质：顶层模块总览
> 设计体系：9 个业务子模块 + 1 个最终收口子模块

## 1. 模块定位

本系统更接近仓库管理与经营记账系统，不按电商 / POS 的“订单—支付—退款”模型设计。

本模块围绕一次“销售出库 / 卖货记录”的完整生命周期展开：

```text
选择商品
→ 数量 / 单位 / 成交价
→ 可选客户
→ 应收 / 实收 / 欠款
→ 出库
→ 库存减少
→ 形成可追溯的出库 / 销售记录
```

当前不把“客户退货 / 退款”作为标准销售子模块。若后续确认真实业务确有该场景，再单独判断应建模为入库、原出库冲销，还是独立退回业务。

## 4. 模块边界

- **01 账户与身份**：提供当前用户、Merchant、角色与权限上下文。
- **04 商品与库存**：拥有商品与通用库存生命周期；本模块只定义一次销售出库造成的库存变化。
- **05 往来与资金**：拥有外部往来对象、通用往来余额、记账账户和后续收付款；本模块负责本次出库的客户关联、当次实收和由本次销售形成的欠款。
- **06 经营分析**：消费出库 / 销售记录形成统计与分析。
- **07 Agent**：通过同一业务服务查询、生成草稿与确认执行，不复制出库规则。
- **08 平台管理与数据迁移**：SYSTEM_ADMIN 通过受控业务服务纠错和审计，Legacy 数据按迁移规则进入新模型。
