# 03 — 客户关联与欠款

> 状态：仓库经营记账边界已校准；具体需求详细设计仍未开始（NOT STARTED）
> 所属模块：02 出库 / 销售

## 设计目标

定义销售出库与外部往来对象 CUSTOMER 角色之间的关系，以及未收金额如何形成客户欠款。

## 后续讨论范围

- 全额现结是否必须选择客户；
- 有欠款时是否必须关联客户；
- CUSTOMER 角色的现场新增 / 补充；
- 同一往来对象角色增加；
- 部分收款与全额未收；
- 客户欠款何时形成；
- 停用客户与历史出库记录；
- 无客户销售的业务边界。

## 边界

客户基础资料完整生命周期属于“05 往来与资金”；本文件只处理销售出库中的客户关联与欠款。

---

## 2026-10-11 范围校准：客户与欠款不是支付网关的未支付订单

系统面向单仓进销存，**不调用外部支付接口**。“已收”“未收”“客户欠款”均指经营人员依据现实交易作出的**账面记录**，不能由第三方支付状态自动推断。

重要边界：

- 销售出库的核心是实际货物离库和库存/销售历史；有无客户信息是否影响出库、是否必须同步登记已收/未收，仍待 W-03/W-04/W-05 确认。
- 不能将“尚未填写实收金额”直接推导为“客户欠款 = 销售全额”，也不能直接视为“已全额收款”。区分**未录入**与**明确 0 元已收**是重要分析内容。
- 一笔有欠款的销售是否必须关联一个 CUSTOMER（或允许匿名未收）、是否支持先出库再补齐客户档案，仍待产品明确。用户没有授权我们把所有仓库出库强制变为对客销售。
- Draft 阶段不创建正式客户欠款；若用户确认业务记录时需要形成正式应收/欠款，则使用内账业务事实，绝不依赖外部付款成功回调。
- 账本真实收款属于模块 02-04 的**人工经营记账**，后续债务归还属于顶层模块 05 往来与资金；不要引入线上支付单或催付订单状态机。
- 时间模型要区分现实业务发生时间与系统录入时间，是否可以补录需 W-02 决策。
