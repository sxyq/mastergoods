# 04 — 当次已发生收款的人工记账（原文件名：当次收款与结算）

> 状态：**第二轮范围定位更正；具体业务详细设计仍待开展（NOT STARTED）**
> 所属模块：02 出库 / 销售

## 设计目标

在**不提供任何外部支付接口**的仓库进销存系统中，明确一次销售出库如存在现实中已发生的收款，是否、何时、由谁在系统**手工登记**已收金额、未收金额及记账账户，及其与销售库存记录的关联。**不是支付网关/收银台/在线结算模块**。

## 后续讨论范围

- 实收默认值；
- 全额、部分、零收款；
- 实收大于应收；
- 找零；
- 单账户 / 多账户收款；
- 现金、微信、支付宝、银行卡等记账账户；
- 当次结算与后续客户还款的边界；
- **本地经营记账写入失败**、重复提交和错误记录更正；非微信/支付宝支付失败或退款回调。

后续客户归还欠款主要属于“05 往来与资金”；本文件只处理销售出库当次结算。

---

## 2026-10-11 范围纠偏（在模块 02 第二轮仓库业务校准期间）

### 必须排除的系统能力

**已由用户明确**：系统不对外提供支付接口，不调用微信支付/支付宝/银行卡支付网关，不生成线上支付单、收银二维码，不等待支付回调、到账确认或在线退款回调，不处理真实资金清算。因此“结算”一词在本文件仅指**经营账面核算/记录**，不是第三方付款通道状态机。

以下词义必须校正：
- “收款” = 用户记录现实中已收到的金额；不是由软件发起收款。
- “现金/微信/支付宝/银行卡” = 如果确有经营记账需要，可以作为已经收到的钱的**账本账户或备注**，不能推断具有资金控制能力。
- “找零” = 现实中可能存在的现金差额处理，**是否需要系统管理仍待确认**；不能预设 POS 找零是必需的。
- “付款失败/结算失败” = 此场景若有失败只能是本地业务录入/事务错误；没有外部支付失败码。

### 开始本子模块正式分析前必须获得答案

1. 用户可以只登记销售出库而不填实收吗？此时未填写与明确实收 0 是否区分？（W-03）
2. 现金现实中已发生，但这笔仓库卖货是否必须在出库时同步登记？允许以后补录吗？（W-05）
3. 本次实收少于商品金额时，何时正式形成客户欠款、要不要客户？（W-04 / 02-03）
4. 系统是否需要支持多种手工账本账户、一次销售多个已收条目；以及错账如何冲销？（待详细设计）
5. 如果实收大于销售金额，是否允许记录现金找零？不把这设为 POS 必需流程；需用户确认。
6. 已完成销售更正后，关联实际收款/欠款怎样更正且保留来源？（02-08 / 02-10）

**禁止的默认决策**：没有真实实收字段就默认“已付清”、强制选择微信支付等渠道、收款失败导致“支付订单状态取消”、自动发起退款、余额扣减等均不得从此文件推导。
