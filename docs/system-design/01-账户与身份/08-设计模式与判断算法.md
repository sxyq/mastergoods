# 01.8 — 账户模块设计模式与判断算法

> 目标：把“用了某某设计模式”进一步落成可实现规则。

---

# 1. Verification Strategy + Registry

输入：

```text
method
target
purpose
```

算法：

```text
strategy = registry[method]
if nil -> UNSUPPORTED_METHOD
if !config.enabled(method) -> METHOD_DISABLED

normalized = strategy.NormalizeTarget(target)
return strategy, normalized
```

Registry 平均 O(1)。

---

# 2. Identifier Resolver

输入原始字符串，输出：

```text
identifier_type
normalized_value
```

优先客户端明确类型；统一输入框再使用标准 Parser。

不要只用 contains("@") 这种脆弱逻辑。

DB 查询唯一索引：

```text
(identifier_type, normalized_value)
```

---

# 3. CanRegisterOwner Specification

```text
Invitation ACTIVE_UNBOUND
AND owner_used = 0
AND Verification valid
AND User not bound to Merchant
```

否则返回明确内部 Reason Code。

---

# 4. CanRegisterStaff Specification

```text
Invitation ACTIVE_BOUND
AND owner_used = 1
AND staff_used < staff_limit
AND Verification valid
AND User has no Merchant Membership
```

---

# 5. STAFF 配额原子算法

```text
UPDATE invitations
SET staff_used = staff_used + 1
WHERE id = :id
  AND status = 'ACTIVE_BOUND'
  AND staff_used < staff_limit
RETURNING staff_used;
```

Membership 创建与配额消耗同事务。

---

# 6. Login Policy Pipeline

顺序建议：

```text
CredentialPolicy
UserStatusPolicy
MembershipStatusPolicy
MerchantStatusPolicy
SecurityStatePolicy
RiskPolicy
```

输出：

```text
ALLOW
STEP_UP
DENY
RECOVERY_REQUIRED
```

---

# 7. Session 有效算法

```text
if token.expired -> INVALID
if session.revoked -> INVALID
if token.epoch != user.epoch -> INVALID
if user.status != ACTIVE -> INVALID
if membership.status != ACTIVE -> INVALID
if merchant.status != ACTIVE -> BUSINESS_DENY
if security_state requires reset -> RECOVERY_ONLY
else VALID
```

---

# 8. Session 全量撤销

目标 O(1)：

```text
user.security_epoch += 1
```

当前设备若保留，重新签发新 epoch Token。

---

# 9. Password Reset Strategy Resolver

```text
User + CURRENT_PASSWORD -> SelfCurrentPasswordReset
User + PHONE -> SelfPhoneVerifiedReset
User + EMAIL -> SelfEmailVerifiedReset

OWNER + STAFF + RANDOM -> OwnerRandomTemporaryReset

SYSTEM_ADMIN + RANDOM -> AdminRandomTemporaryReset
SYSTEM_ADMIN + DEFINED -> AdminDefinedPasswordReset
SYSTEM_ADMIN + REQUIRE_RECOVERY -> AdminRequireSelfRecovery
```

未列组合默认 DENY。

---

# 10. Temporary Credential

有效条件：

```text
exists
AND ACTIVE
AND now < expires_at
AND used_at IS NULL
AND attempts < max_attempts
AND target account not globally disabled
```

成功后立即标记 USED。

---

# 11. Password Policy Engine

Policy 列表：

```text
LengthPolicy
CommonPasswordPolicy
IdentifierSimilarityPolicy
HistoryPolicy（如启用）
```

返回：

```text
PASS
或 code + reason
```

SYSTEM_ADMIN 直接设置也经过同一 Engine。

---

# 12. Risk Rule Composite

每个 Rule：

```text
Evaluate(context) -> matched, weight, reason
```

```text
score = sum(weight)
```

阈值：

```text
score < T1 -> LOW
T1..T2 -> MEDIUM
T2..T3 -> HIGH
>=T3 -> CRITICAL
```

记录 matched rule ids。

---

# 13. Rate Limit

通过统一接口：

```text
RateLimiter.Allow(key, policy)
```

可以使用 Sliding Window 或 Token Bucket。

---

# 14. Outbox Retry

```text
delay = min(max_delay, base * 2^attempt)
delay += random_jitter
```

永久错误不无限重试。

---

# 15. Idempotency

Key：

```text
scope + idempotency_key
```

状态：

```text
PROCESSING
SUCCEEDED
FAILED_RETRYABLE
FAILED_FINAL
```

随机密码 Reset 例外：

- 首次返回明文；
- 重放不再返回明文；
- 丢失只能发起新 Reset。

---

# 16. Audit Interceptor

高风险 Command：

```text
Authorize
→ Load Before
→ Execute
→ Build After
→ Audit
→ Commit
```

Audit：

```text
operator
target
merchant
action
before
after
reason
result
time
```

绝不写密码、OTP、Token 明文。

# 17. 完整状态机矩阵（08-04 收口）

本节把状态列表落实为可实现的迁移契约。每一行都必须明确旧状态、事件、操作者、前置条件、新状态、副作用和 Audit；未列出的迁移一律拒绝。`current_state`、`expected_version` 和 `policy_version` 必须在同一个写事务中校验并记录。

## 17.1 Invitation

| 旧状态 | 事件 | 操作者 | 前置条件 | 新状态 | 副作用 / Audit |
|---|---|---|---|---|---|
| CREATED | `ACTIVATE_INVITATION` | SYSTEM_ADMIN | 配额、有效期和策略配置合法 | ACTIVE_UNBOUND | 记录创建和启用；写入 policy_version |
| ACTIVE_UNBOUND | `OWNER_REGISTERED` | OWNER / Registration Service | OWNER 配额未使用；User 没有 Merchant Membership；Merchant 创建事务成功 | ACTIVE_BOUND | 创建 Merchant + OWNER Membership，绑定 invitation；同事务写 Audit |
| ACTIVE_UNBOUND | `DISABLE_INVITATION` | SYSTEM_ADMIN | 尚未绑定 Merchant | DISABLED | 禁止后续注册；记录 reason_code |
| ACTIVE_UNBOUND | `EXPIRE_INVITATION` | System Job | 当前时间超过 expires_at | EXPIRED | 禁止后续注册；记录过期原因 |
| ACTIVE_BOUND | `STAFF_REGISTERED` | STAFF / Registration Service | Merchant ACTIVE；staff_used < staff_limit；User 无有效 Membership | ACTIVE_BOUND | 创建 STAFF User + Membership，staff_used + 1；记录注册 Audit |
| ACTIVE_BOUND | `STAFF_REGISTERED_LAST_SLOT` | STAFF / Registration Service | 本次注册消耗最后一个 STAFF 配额 | EXHAUSTED | 创建 Membership、更新配额并记录 Audit |
| ACTIVE_BOUND | `DISABLE_INVITATION` | SYSTEM_ADMIN | Merchant 未关闭或已进入停用流程 | DISABLED | 立即拒绝新 STAFF 注册；记录 Audit |
| ACTIVE_BOUND | `EXPIRE_INVITATION` | System Job | 当前时间超过 expires_at | EXPIRED | 保留历史注册关系；禁止新增注册 |
| EXHAUSTED | `INCREASE_STAFF_LIMIT` | SYSTEM_ADMIN | 新上限大于 staff_used；未过期、未禁用 | ACTIVE_BOUND | 更新配置版本；记录配额变更 Audit |
| DISABLED | `REACTIVATE_INVITATION` | SYSTEM_ADMIN | 未过期；恢复原因和原绑定关系可审计 | ACTIVE_UNBOUND 或 ACTIVE_BOUND | 恢复到停用前的 active 状态；写入恢复 Audit |
| EXPIRED | 任意注册 / 恢复 | 任意 | 终态 | 拒绝 | 不产生 User、Membership 或配额副作用；写入拒绝事件 |

`EXHAUSTED`、`DISABLED`、`EXPIRED` 不允许被注册请求隐式恢复；只有明确命令才能触发允许的恢复迁移。

## 17.2 User Account Status

| 旧状态 | 事件 | 操作者 | 前置条件 | 新状态 | 副作用 / Audit |
|---|---|---|---|---|---|
| — | `REGISTER_USER` | User / Registration Service | 注册准入、身份验证和幂等校验通过 | ACTIVE | 创建 User、标识和密码凭据；写注册 Audit |
| — | `PROVISION_SYSTEM_ADMIN` | Bootstrap / SYSTEM_ADMIN | 受控部署或管理员创建流程 | ACTIVE | 创建平台账号；写高风险 Audit |
| ACTIVE | `DISABLE_USER` | SYSTEM_ADMIN 或账号关闭流程 | 通过权限、原因和最后 OWNER 保护规则 | DISABLED | 撤销全部 Session；保留历史记录；写 Audit |
| DISABLED | `RESTORE_USER` | SYSTEM_ADMIN | 恢复原因、权限和风险复核通过 | ACTIVE | 不恢复旧 Session；按策略重新设置 Security State；写 Audit |
| DISABLED | `LOGIN` / `RESET_PASSWORD` | 任意 | User status 不是 ACTIVE | DISABLED | 拒绝登录；重置密码不自动恢复账号；写 Security Event |

## 17.3 Security State

`DISABLED` 不属于 Security State。账号是否停用只看 `User Account Status`；本状态机只表示安全挑战、密码恢复和临时锁定条件。

| 旧状态 | 事件 | 操作者 | 前置条件 | 新状态 | 副作用 / Audit |
|---|---|---|---|---|---|
| — | `ACCOUNT_ACTIVATED` | Registration Service | User Account Status = ACTIVE | NORMAL | 初始化安全策略版本；写状态 Audit |
| NORMAL | `REQUIRE_STEP_UP` | Risk Engine / Service | 命中需要二次证明的规则 | STEP_UP_REQUIRED | 创建 Challenge；写 risk_evaluation_ref |
| STEP_UP_REQUIRED | `VERIFY_STEP_UP` | User | Challenge VERIFIED，未过期、未超次数 | NORMAL | 记录 proof_id；按策略轮换 Session |
| STEP_UP_REQUIRED | `STEP_UP_FAILED` | User / Risk Engine | 失败次数达到阈值 | TEMPORARY_LOCKED | 撤销高风险操作相关 Session；写 Risk Event |
| NORMAL | `REQUIRE_PASSWORD_RESET` | SYSTEM_ADMIN / Risk Engine | 管理员强制重置或风险规则命中 | PASSWORD_RESET_REQUIRED | 创建 Temporary Credential；撤销受影响 Session |
| PASSWORD_RESET_REQUIRED | `PASSWORD_RESET_SUCCEEDED` | User | 新密码通过 Password Policy | NORMAL | 旧临时凭据失效；按策略保留当前设备并撤销其他 Session |
| PASSWORD_RESET_REQUIRED | `RESET_FAILED_LIMIT` | Risk Engine | 恢复失败达到阈值 | TEMPORARY_LOCKED | 撤销相关 Session；写 Risk Event |
| NORMAL | `LOCK_FOR_RISK` | Risk Engine / SYSTEM_ADMIN | 风险达到临时锁定阈值 | TEMPORARY_LOCKED | 拒绝登录；写 reason_code 和 policy_version |
| TEMPORARY_LOCKED | `LOCK_COOLDOWN_ELAPSED` | System Job | 冷却时间结束且无新的硬规则 | NORMAL | 写解锁 Audit；不恢复已撤销 Session |
| TEMPORARY_LOCKED | `ADMIN_RELEASE_LOCK` | SYSTEM_ADMIN | 风险复核和解锁原因完整 | NORMAL | 写人工解锁 Audit |

## 17.4 Membership

| 旧状态 | 事件 | 操作者 | 前置条件 | 新状态 | 副作用 / Audit |
|---|---|---|---|---|---|
| — | `OWNER_MEMBERSHIP_CREATED` | Registration Service | OWNER 注册事务创建 Merchant | ACTIVE | 创建唯一 OWNER Membership；写注册 Audit |
| — | `STAFF_MEMBERSHIP_CREATED` | Registration Service | STAFF 使用已绑定 MerchantInvitation 注册且无有效 Membership | ACTIVE | 创建 STAFF Membership、消耗配额；写注册 Audit |
| ACTIVE | `DISABLE_MEMBERSHIP` | OWNER（STAFF）/ SYSTEM_ADMIN | 权限、原因和最后 OWNER 保护规则通过 | DISABLED | 立即撤销该 Merchant 相关 Session；保留历史操作者；写 Audit |
| ACTIVE | `TRANSFER_OWNER` | OWNER / SYSTEM_ADMIN | 新 OWNER 已验证且交接事务满足唯一 OWNER 约束 | ACTIVE | 原 OWNER 按已确认交接规则变更角色或退出；写前后快照 Audit |
| DISABLED | `RESTORE_MEMBERSHIP` | OWNER / SYSTEM_ADMIN | User status = ACTIVE、无其他有效 Merchant Membership、重新授权通过 | ACTIVE | 创建新的 Session 前重新完成登录；写恢复 Audit |
| DISABLED | `LOGIN_IN_MERCHANT` | 任意 | Membership 不是 ACTIVE | DISABLED | 拒绝进入该 Merchant；写 Security Event |

## 17.5 Merchant Status

| 旧状态 | 事件 | 操作者 | 前置条件 | 新状态 | 副作用 / Audit |
|---|---|---|---|---|---|
| — | `CREATE_MERCHANT` | Registration Service | OWNER 注册事务通过 | ACTIVE | 创建唯一 OWNER Membership；写创建 Audit |
| ACTIVE | `FREEZE_MERCHANT` | SYSTEM_ADMIN | 原因、影响范围和恢复责任人明确 | FROZEN | 禁止普通业务写入；已有历史数据可按后台权限读取；写 Audit |
| FROZEN | `UNFREEZE_MERCHANT` | SYSTEM_ADMIN | 风险或运营复核通过 | ACTIVE | 恢复业务入口；写恢复 Audit |
| ACTIVE / FROZEN | `CLOSE_MERCHANT` | SYSTEM_ADMIN / 受控关闭流程 | 成员、数据保留和恢复规则满足 | CLOSED | 撤销相关 Session；禁止新 Invitation 注册；写关闭 Audit |
| CLOSED | 任意普通业务操作 | 任意 | 终态 | CLOSED | 拒绝，不产生业务副作用；写拒绝事件 |

## 17.6 Session

| 旧状态 | 事件 | 操作者 | 前置条件 | 新状态 | 副作用 / Audit |
|---|---|---|---|---|---|
| — | `CREATE_SESSION` | Login Service | User ACTIVE、Membership ACTIVE、Merchant ACTIVE、Security State 允许登录 | ACTIVE | 创建设备 Session；保存 policy_version |
| ACTIVE | `ROTATE_TOKEN` | Session Service | Session 未撤销、Token 未过期 | ROTATED | 旧 Token 立即失效；同一 Session 内轮换 |
| ROTATED | `ROTATE_TOKEN` | Session Service | Session 仍有效 | ROTATED | 更新 Token 引用和过期时间；不创建新设备 Session |
| ACTIVE / ROTATED | `REVOKE_SESSION` | User / SYSTEM_ADMIN / Security Command | 操作权限或密码变更规则通过 | REVOKED | 立即拒绝后续请求；写 Session Audit |
| ACTIVE / ROTATED | `EXPIRE_SESSION` | Session Service / System Job | TTL 到期或安全 epoch 不匹配 | EXPIRED | 清除刷新资格；写过期事件 |
| REVOKED / EXPIRED | 任意刷新或业务请求 | 任意 | 终态 | 拒绝 | 不重新激活；写 Security Event |

## 17.7 Verification Challenge

| 旧状态 | 事件 | 操作者 | 前置条件 | 新状态 | 副作用 / Audit |
|---|---|---|---|---|---|
| — | `CREATE_CHALLENGE` | Verification Service | Purpose、Method、Target 和 Policy 合法 | CREATED | 保存不可逆目标引用和 policy_version |
| CREATED | `DISPATCH_CHALLENGE` | Outbox Worker | Provider 配置启用且发送请求成功 | SENT | 记录 provider_request_ref；不保存验证码明文 |
| CREATED / SENT | `EXPIRE_CHALLENGE` | System Job | 当前时间超过 expires_at | EXPIRED | 拒绝后续验证；写过期事件 |
| SENT | `VERIFY_SUCCESS` | User | 输入正确、未过期、attempt 未超限 | VERIFIED | 生成 proof_id；写验证 Audit |
| SENT | `VERIFY_FAILURE_LIMIT` | User / Verification Service | 失败次数达到 max_attempts | ATTEMPT_EXCEEDED | 触发 Risk；拒绝后续尝试 |
| CREATED / SENT | `REVOKE_CHALLENGE` | New Challenge / Security Command | 同 Purpose 新挑战替代旧挑战，或管理员撤销 | REVOKED | 旧挑战不可重放；写撤销 Audit |

## 17.8 Temporary Credential

| 旧状态 | 事件 | 操作者 | 前置条件 | 新状态 | 副作用 / Audit |
|---|---|---|---|---|---|
| — | `ISSUE_TEMPORARY_CREDENTIAL` | OWNER / SYSTEM_ADMIN / Recovery Service | 权限、原因和 Password Policy 通过 | ACTIVE | 只保存 Hash；明文只显示一次；写 Audit |
| ACTIVE | `USE_TEMPORARY_CREDENTIAL` | User | 凭据正确、未过期、未锁定 | USED | 强制进入 PASSWORD_RESET_REQUIRED；旧凭据不可重放 |
| ACTIVE | `EXPIRE_TEMPORARY_CREDENTIAL` | System Job | 当前时间超过 expires_at | EXPIRED | 拒绝使用；写过期事件 |
| ACTIVE | `FAIL_ATTEMPT_LIMIT` | Risk Engine | 输入失败达到阈值 | LOCKED | 拒绝继续尝试；写 Risk Event |
| ACTIVE / LOCKED | `REVOKE_TEMPORARY_CREDENTIAL` | New Reset / SYSTEM_ADMIN | 新 Reset 或账号状态变化 | REVOKED | 旧凭据立即失效；写撤销 Audit |
| USED / EXPIRED / REVOKED | 任意再次使用 | 任意 | 终态 | 拒绝 | 不返回明文；写重放或失败事件 |

## 17.9 统一迁移约束

每次迁移必须同时具备：

```text
old_state = expected_state
event + actor + reason_code
precondition / policy_version
new_state + expected_version -> new_version
副作用计划（Session、Challenge、配额、Outbox）
Audit（before、after、result、occurred_at）
```

并发版本冲突返回 `CONFLICT`；非法路径返回 `INVALID`；权限或业务前置条件失败返回 `DENIED`。任何 Handler 不得直接写入未经矩阵允许的状态值。

# 20. 决策字段设计

本节补充每个判断系统需要携带的概念字段。字段用于统一 Policy、Strategy、Command、State Machine、Audit 和后续实现；它不是数据库表定义，也不是对外 API 契约。

## 20.1 字段分类

| 分类 | 典型字段 | 规则 |
|---|---|---|
| Stable Reference | user_id、merchant_id、membership_id、session_id | 使用稳定引用，不用手机号、邮箱或 Token 代替 |
| Decision Input | purpose、requested_role、method、target_scope | 进入 Policy 前完成规范化 |
| State | status、security_state、credential_state | 只能通过合法状态迁移修改 |
| Version | policy_version、strategy_version、config_version | 保留历史判定依据 |
| Security Evidence | rule_id、risk_score、proof_id、device_ref、ip_ref | 可解释但不携带秘密 |
| Idempotency | idempotency_key、request_digest、command_state | 防止重复副作用 |

状态字段必须保持职责分离：

| 对象 | 状态字段 | 允许值 |
|---|---|---|
| User Account | `account_status` | `ACTIVE`、`DISABLED` |
| User Security | `security_state` | `NORMAL`、`STEP_UP_REQUIRED`、`PASSWORD_RESET_REQUIRED`、`TEMPORARY_LOCKED` |
| Membership | `membership_status` | `ACTIVE`、`DISABLED` |
| Merchant | `merchant_status` | `ACTIVE`、`FROZEN`、`CLOSED` |
| Session | `session_state` | `ACTIVE`、`ROTATED`、`REVOKED`、`EXPIRED` |
| Challenge | `challenge_state` | `CREATED`、`SENT`、`VERIFIED`、`EXPIRED`、`REVOKED`、`ATTEMPT_EXCEEDED` |
| Temporary Credential | `credential_state` | `ACTIVE`、`USED`、`EXPIRED`、`LOCKED`、`REVOKED` |

`DISABLED` 只能出现在 User Account 或 Membership 的状态字段中，不能写入 `security_state`。
| Audit | actor、target、reason、before、after、result、occurred_at | 记录高风险动作 |
| Secret Material | password、code、token、API key | 不进入持久化明文、日志或 Audit |

## 20.2 Decision Context 通用字段

每次注册、登录、恢复、改密、停用和强制下线都先构造统一 Context：

| 字段 | 含义 | 约束 |
|---|---|---|
| request_id | 本次请求引用 | 每次请求唯一 |
| correlation_id | 跨 Policy、Command、Outbox 的关联引用 | 同一业务操作保持不变 |
| idempotency_key | 写命令重试引用 | 注册、Reset、结算等高风险命令必需 |
| request_digest | 去除秘密后的参数摘要 | 不能含密码、验证码或 Token |
| actor_user_id | 操作者 User | 匿名注册可为空 |
| actor_role | SYSTEM_ADMIN、OWNER、STAFF、ANONYMOUS | 来自服务端身份 |
| target_user_id | 被操作 User | 自助操作可等于 actor |
| merchant_id | 目标 Merchant | SYSTEM_ADMIN 平台操作可为空 |
| membership_id | 目标 Membership | 跨 Merchant 作用域必须拒绝 |
| purpose | REGISTER、LOGIN、PASSWORD_RESET 等 | 参与限流、Proof 和策略选择 |
| requested_role | OWNER 或 STAFF | 只在注册、交接出现 |
| method | PHONE、EMAIL 或未来方法 | 由 Registry 解析 |
| normalized_identifier_ref | 标识的不可逆引用 | 不保存完整联系信息 |
| device_ref | 设备受控引用 | 用于 Session 和 Risk |
| ip_ref | IP 受控引用 | 用于限流和 Risk |
| expected_version | 调用者读取的状态版本 | 防止并发覆盖 |
| policy_version | 本次规则版本 | 写入 Decision 和 Audit |
| occurred_at | 服务端接收时间 | 不信任客户端时间 |

## 20.3 Registration Decision 字段

| 字段 | 含义 |
|---|---|
| invitation_ref | 邀请码受控引用 |
| invitation_state | CREATED、ACTIVE_UNBOUND、ACTIVE_BOUND、EXHAUSTED、EXPIRED、DISABLED |
| requested_role | OWNER 或 STAFF |

## 20.11 配置和版本字段

以下配置必须保存版本引用，不能只覆盖当前值：

| 配置 | 关键字段 |
|---|---|
| Registration Policy | owner_limit、staff_limit、merchant_state_rules、policy_version |
| Password Policy | length、guessability、reuse、KDF 参数引用、first_change_rule、policy_version |
| Verification Policy | method、TTL、cooldown、max_attempts、rate_limit、strategy_version |
| Risk Policy | rule_id、weight、window、decay、threshold、hard_rule、risk_policy_version |
| Session Policy | sliding_ttl、rotation、device_binding、session_policy_version |
| Provider Config | provider_key、base_url 引用、credential_ref、headers 版本、provider_config_version |
| Agent Pricing | pricing_version、input_usd、output_usd、cached_input_usd、usd_to_points_version |

旧 Challenge、旧 Session、历史 Task 和 Model Call 必须继续引用创建时的版本；发布新版本不能重算历史事实。

## 20.12 字段级不变量

1. Stable Reference 不用手机号、邮箱、邀请码或 Token 代替。
2. 状态字段只能通过合法迁移改变。
3. Decision、Challenge、Session、Reset 和 Task 都能追溯 Policy、Strategy 或 Config Version。
4. 高风险写操作都有 Idempotency Key，或明确记录无需幂等的原因。
5. 并发命令都有 expected_version 或等价的原子条件。
6. 外部发送都有 Outbox Event 和 Retry 状态。
7. 密码、验证码、临时凭据、Token 和 API Key 不进入明文持久化。
8. Audit 能回答谁、对哪个对象、基于什么规则、做了什么、结果如何，但不泄露秘密。
9. Agent 积分 Ledger、USD 成本、Pricing Version 和 Settlement Reference 可以互相追溯。
10. TTL、限流数值、密码长度、阈值、KDF 参数和 Provider 属于配置，不冒充产品关系。

# 21. 08 的收口状态

完成本节完整状态机矩阵、字段语义和统一迁移约束后，账户与身份模块可标记为：

~~~text
Status: DESIGN FROZEN v1
~~~

这表示业务流程、模块边界、核心 Decision、状态机、并发幂等、字段语义和版本追踪足以支撑领域模型、数据库 Schema、API 和编码。具体 TTL、限流数量、Argon2id 参数、短信/邮件供应商和运维阈值继续作为版本化实现配置。
