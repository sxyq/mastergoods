# 01.8 — 账户模块设计模式与判断算法

> 目标：把“用了某某设计模式”进一步落成可实现规则。

---

# 1. Verification Strategy + Registry

输入：

```text
method
target
purpose
```

算法：

```text
strategy = registry[method]
if nil -> UNSUPPORTED_METHOD
if !config.enabled(method) -> METHOD_DISABLED

normalized = strategy.NormalizeTarget(target)
return strategy, normalized
```

Registry 平均 O(1)。

---

# 2. Identifier Resolver

输入原始字符串，输出：

```text
identifier_type
normalized_value
```

优先客户端明确类型；统一输入框再使用标准 Parser。

不要只用 contains("@") 这种脆弱逻辑。

DB 查询唯一索引：

```text
(identifier_type, normalized_value)
```

---

# 3. CanRegisterOwner Specification

```text
Invitation ACTIVE_UNBOUND
AND owner_used = 0
AND Verification valid
AND User not bound to Merchant
```

否则返回明确内部 Reason Code。

---

# 4. CanRegisterStaff Specification

```text
Invitation ACTIVE_BOUND
AND owner_used = 1
AND staff_used < staff_limit
AND Verification valid
AND User has no Merchant Membership
```

---

# 5. STAFF 配额原子算法

```text
UPDATE invitations
SET staff_used = staff_used + 1
WHERE id = :id
  AND status = 'ACTIVE_BOUND'
  AND staff_used < staff_limit
RETURNING staff_used;
```

Membership 创建与配额消耗同事务。

# 6. Login Policy Pipeline

顺序建议：

```text
CredentialPolicy
UserStatusPolicy
MembershipStatusPolicy
MerchantStatusPolicy
SecurityStatePolicy
RiskPolicy
```

输出：

```text
ALLOW
STEP_UP
DENY
RECOVERY_REQUIRED
```

---

# 7. Session 有效算法

```text
if token.expired -> INVALID
if session.revoked -> INVALID
if token.epoch != user.epoch -> INVALID
if user.status != ACTIVE -> INVALID
if membership.status != ACTIVE -> INVALID
if merchant.status != ACTIVE -> BUSINESS_DENY
if security_state requires reset -> RECOVERY_ONLY
else VALID
```

---

# 8. Session 全量撤销

目标 O(1)：

```text
user.security_epoch += 1
```

当前设备若保留，重新签发新 epoch Token。

---

# 9. Password Reset Strategy Resolver

```text
User + CURRENT_PASSWORD -> SelfCurrentPasswordReset
User + PHONE -> SelfPhoneVerifiedReset
User + EMAIL -> SelfEmailVerifiedReset

OWNER + STAFF + RANDOM -> OwnerRandomTemporaryReset

SYSTEM_ADMIN + RANDOM -> AdminRandomTemporaryReset
SYSTEM_ADMIN + DEFINED -> AdminDefinedPasswordReset
SYSTEM_ADMIN + REQUIRE_RECOVERY -> AdminRequireSelfRecovery
```

未列组合默认 DENY。

---

# 10. Temporary Credential

有效条件：

```text
exists
AND ACTIVE
AND now < expires_at
AND used_at IS NULL
AND attempts < max_attempts
AND target account not globally disabled
```

成功后立即标记 USED。

---

# 11. Password Policy Engine

Policy 列表：

```text
LengthPolicy
CommonPasswordPolicy
IdentifierSimilarityPolicy
HistoryPolicy（如启用）
```

返回：

```text
PASS
或 code + reason
```

SYSTEM_ADMIN 直接设置也经过同一 Engine。

---

# 12. Risk Rule Composite

每个 Rule：

```text
Evaluate(context) -> matched, weight, reason
```

```text
score = sum(weight)
```

阈值：

```text
score < T1 -> LOW
T1..T2 -> MEDIUM
T2..T3 -> HIGH
>=T3 -> CRITICAL
```

记录 matched rule ids。

---

# 13. Rate Limit

通过统一接口：

```text
RateLimiter.Allow(key, policy)
```

可以使用 Sliding Window 或 Token Bucket。

---

# 14. Outbox Retry

```text
delay = min(max_delay, base * 2^attempt)
delay += random_jitter
```

永久错误不无限重试。

---

# 15. Idempotency

Key：

```text
scope + idempotency_key
```

状态：

```text
PROCESSING
SUCCEEDED
FAILED_RETRYABLE
FAILED_FINAL
```

随机密码 Reset 例外：

- 首次返回明文；
- 重放不再返回明文；
- 丢失只能发起新 Reset。

---

# 16. Audit Interceptor

高风险 Command：

```text
Authorize
→ Load Before
→ Execute
→ Build After
→ Audit
→ Commit
```

Audit：

```text
operator
target
merchant
action
before
after
reason
result
time
```

绝不写密码、OTP、Token 明文。

---

# 17. State Machine

建议至少：

```text
InvitationStateMachine
SecurityStateMachine
TemporaryCredentialStateMachine
SessionStateMachine
```

Handler 不能直接随意写状态字符串。

---

# 18. 高频索引

高频路径：

```text
Login Identifier
Session
Membership
Invitation
Point Account
Security Events by time window
```

均需索引。

Risk 不应每次扫描全部历史事件；使用时间范围索引，规模上升再做 Counter / Redis。
