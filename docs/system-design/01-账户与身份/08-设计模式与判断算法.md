# 01.8 — 账户模块设计模式与判断算法

> 目标：把“用了某某设计模式”进一步落成可实现规则。

---

# 1. Verification Strategy + Registry

输入：

```text
method
target
purpose
```

算法：

```text
strategy = registry[method]
if nil -> UNSUPPORTED_METHOD
if !config.enabled(method) -> METHOD_DISABLED

normalized = strategy.NormalizeTarget(target)
return strategy, normalized
```

Registry 平均 O(1)。

---

# 2. Identifier Resolver

输入原始字符串，输出：

```text
identifier_type
normalized_value
```

优先客户端明确类型；统一输入框再使用标准 Parser。

不要只用 contains("@") 这种脆弱逻辑。

DB 查询唯一索引：

```text
(identifier_type, normalized_value)
```

---

# 3. CanRegisterOwner Specification

```text
Invitation ACTIVE_UNBOUND
AND owner_used = 0
AND Verification valid
AND User not bound to Merchant
```

否则返回明确内部 Reason Code。

---

# 4. CanRegisterStaff Specification

```text
Invitation ACTIVE_BOUND
AND owner_used = 1
AND staff_used < staff_limit
AND Verification valid
AND User has no Merchant Membership
```

---

# 5. STAFF 配额原子算法

```text
UPDATE invitations
SET staff_used = staff_used + 1
WHERE id = :id
  AND status = 'ACTIVE_BOUND'
  AND staff_used < staff_limit
RETURNING staff_used;
```

Membership 创建与配额消耗同事务。

---

# 6. Login Policy Pipeline

顺序建议：

```text
CredentialPolicy
UserStatusPolicy
MembershipStatusPolicy
MerchantStatusPolicy
SecurityStatePolicy
RiskPolicy
```

输出：

```text
ALLOW
STEP_UP
DENY
RECOVERY_REQUIRED
```

---

# 7. Session 有效算法

```text
if token.expired -> INVALID
if session.revoked -> INVALID
if token.epoch != user.epoch -> INVALID
if user.status != ACTIVE -> INVALID
if membership.status != ACTIVE -> INVALID
if merchant.status != ACTIVE -> BUSINESS_DENY
if security_state requires reset -> RECOVERY_ONLY
else VALID
```

---

# 8. Session 全量撤销

目标 O(1)：

```text
user.security_epoch += 1
```

当前设备若保留，重新签发新 epoch Token。

---

# 9. Password Reset Strategy Resolver

```text
User + CURRENT_PASSWORD -> SelfCurrentPasswordReset
User + PHONE -> SelfPhoneVerifiedReset
User + EMAIL -> SelfEmailVerifiedReset

OWNER + STAFF + RANDOM -> OwnerRandomTemporaryReset

SYSTEM_ADMIN + RANDOM -> AdminRandomTemporaryReset
SYSTEM_ADMIN + DEFINED -> AdminDefinedPasswordReset
SYSTEM_ADMIN + REQUIRE_RECOVERY -> AdminRequireSelfRecovery
```

未列组合默认 DENY。

---

# 10. Temporary Credential

有效条件：

```text
exists
AND ACTIVE
AND now < expires_at
AND used_at IS NULL
AND attempts < max_attempts
AND target account not globally disabled
```

成功后立即标记 USED。

---

# 11. Password Policy Engine

Policy 列表：

```text
LengthPolicy
CommonPasswordPolicy
IdentifierSimilarityPolicy
HistoryPolicy（如启用）
```

返回：

```text
PASS
或 code + reason
```

SYSTEM_ADMIN 直接设置也经过同一 Engine。

---

# 12. Risk Rule Composite

每个 Rule：

```text
Evaluate(context) -> matched, weight, reason
```

```text
score = sum(weight)
```

阈值：

```text
score < T1 -> LOW
T1..T2 -> MEDIUM
T2..T3 -> HIGH
>=T3 -> CRITICAL
```

记录 matched rule ids。

---

# 13. Rate Limit

通过统一接口：

```text
RateLimiter.Allow(key, policy)
```

可以使用 Sliding Window 或 Token Bucket。

---

# 14. Outbox Retry

```text
delay = min(max_delay, base * 2^attempt)
delay += random_jitter
```

永久错误不无限重试。

---

# 15. Idempotency

Key：

```text
scope + idempotency_key
```

状态：

```text
PROCESSING
SUCCEEDED
FAILED_RETRYABLE
FAILED_FINAL
```

随机密码 Reset 例外：

- 首次返回明文；
- 重放不再返回明文；
- 丢失只能发起新 Reset。

---

# 16. Audit Interceptor

高风险 Command：

```text
Authorize
→ Load Before
→ Execute
→ Build After
→ Audit
→ Commit
```

Audit：

```text
operator
target
merchant
action
before
after
reason
result
time
```

绝不写密码、OTP、Token 明文。

---

# 17. State Machine

建议至少：

```text
InvitationStateMachine
SecurityStateMachine
TemporaryCredentialStateMachine
SessionStateMachine
```

Handler 不能直接随意写状态字符串。

---

# 18. 高频索引

高频路径：

```text
Login Identifier
Session
Membership
Invitation
Point Account
Security Events by time window
```

均需索引。

Risk 不应每次扫描全部历史事件；使用时间范围索引，规模上升再做 Counter / Redis。

---

# 19. 已冻结算法方向

1. Verification Strategy Registry；
2. Identifier Resolver；
3. Login Policy Pipeline；
4. Password Reset Strategy Resolver；
5. Password Policy Engine；
6. Risk Weighted Rules；
7. security_epoch；
8. Invitation atomic quota；
9. Idempotency；
10. Outbox backoff + jitter；
11. Audit Interceptor；
12. Index-first 高频查询。

# 20. 决策字段设计

本节补充每个判断系统需要携带的概念字段。字段用于统一 Policy、Strategy、Command、State Machine、Audit 和后续实现；它不是数据库表定义，也不是对外 API 契约。

## 20.1 字段分类

| 分类 | 典型字段 | 规则 |
|---|---|---|
| Stable Reference | user_id、merchant_id、membership_id、session_id | 使用稳定引用，不用手机号、邮箱或 Token 代替 |
| Decision Input | purpose、requested_role、method、target_scope | 进入 Policy 前完成规范化 |
| State | status、security_state、credential_state | 只能通过合法状态迁移修改 |
| Version | policy_version、strategy_version、config_version | 保留历史判定依据 |
| Security Evidence | rule_id、risk_score、proof_id、device_ref、ip_ref | 可解释但不携带秘密 |
| Idempotency | idempotency_key、request_digest、command_state | 防止重复副作用 |
| Audit | actor、target、reason、before、after、result、occurred_at | 记录高风险动作 |
| Secret Material | password、code、token、API key | 不进入持久化明文、日志或 Audit |

## 20.2 Decision Context 通用字段

每次注册、登录、恢复、改密、停用和强制下线都先构造统一 Context：

| 字段 | 含义 | 约束 |
|---|---|---|
| request_id | 本次请求引用 | 每次请求唯一 |
| correlation_id | 跨 Policy、Command、Outbox 的关联引用 | 同一业务操作保持不变 |
| idempotency_key | 写命令重试引用 | 注册、Reset、结算等高风险命令必需 |
| request_digest | 去除秘密后的参数摘要 | 不能含密码、验证码或 Token |
| actor_user_id | 操作者 User | 匿名注册可为空 |
| actor_role | SYSTEM_ADMIN、OWNER、STAFF、ANONYMOUS | 来自服务端身份 |
| target_user_id | 被操作 User | 自助操作可等于 actor |
| merchant_id | 目标 Merchant | SYSTEM_ADMIN 平台操作可为空 |
| membership_id | 目标 Membership | 跨 Merchant 作用域必须拒绝 |
| purpose | REGISTER、LOGIN、PASSWORD_RESET 等 | 参与限流、Proof 和策略选择 |
| requested_role | OWNER 或 STAFF | 只在注册、交接出现 |
| method | PHONE、EMAIL 或未来方法 | 由 Registry 解析 |
| normalized_identifier_ref | 标识的不可逆引用 | 不保存完整联系信息 |
| device_ref | 设备受控引用 | 用于 Session 和 Risk |
| ip_ref | IP 受控引用 | 用于限流和 Risk |
| expected_version | 调用者读取的状态版本 | 防止并发覆盖 |
| policy_version | 本次规则版本 | 写入 Decision 和 Audit |
| occurred_at | 服务端接收时间 | 不信任客户端时间 |

## 20.3 Registration Decision 字段

| 字段 | 含义 |
|---|---|
| invitation_ref | 邀请码受控引用 |
| invitation_state | ACTIVE_UNBOUND、ACTIVE_BOUND、CONSUMED、EXPIRED、DISABLED |
| requested_role | OWNER 或 STAFF |
| owner_limit、owner_used | OWNER 名额快照 |
| staff_limit、staff_used | STAFF 配额快照 |
| merchant_state | Merchant 状态快照 |
| identifier_resolution | NEW、EXISTING、INVALID、AMBIGUOUS |
| identity_proof | VERIFIED、STEP_UP_REQUIRED、NOT_PROVED |
| existing_membership_state | NONE、SAME_MERCHANT、OTHER_MERCHANT、CONFLICT |
| registration_decision | ALLOW 或明确 Reject Reason |
| reject_reason_code | 稳定的内部原因码 |
| required_proof_id | 继续验证时的 Proof 引用 |
| quota_conflict | 是否发生并发配额冲突 |
| idempotency_state | NEW、REPLAY、CONFLICT |
| audit_reference | 注册结果审计引用 |

Registration Decision 只表达判定；User、Merchant、Membership 和配额副作用只能由注册 Command 在事务内提交。

## 20.4 Login Decision 字段

| 字段 | 含义 |
|---|---|
| identifier_type | PHONE、EMAIL 或未来方法 |
| credential_type | 正式密码或临时凭据 |
| credential_result | SUCCESS、FAIL、EXPIRED、USED、LOCKED |
| user_state | User 状态快照 |
| membership_state | Membership 状态快照 |
| merchant_state | Merchant 状态快照 |
| security_state | NORMAL、STEP_UP_REQUIRED、PASSWORD_RESET_REQUIRED、LOCKED |
| hard_rule_result | CONTINUE、HARD_DENY、RECOVERY_ONLY |
| risk_score | Weighted Rule 结果 |
| matched_rule_ids | 命中的风险规则 |
| risk_level | LOW、MEDIUM、HIGH、CRITICAL |
| login_decision | ALLOW、STEP_UP、RESET_REQUIRED、TEMPORARY_LOCK、DENY |
| required_proof_id | Step-up 或恢复 Proof |
| session_action | CREATE、ROTATE、NONE |
| session_policy_version | 期限、Rotation 和设备规则版本 |
| decision_expires_at | 决策有效期 |

内部 Decision 可以区分不存在、密码错误和停用原因；外部登录响应必须避免暴露账号存在性。

### Temporary Credential

| 字段 | 含义 |
|---|---|

## 20.6 Verification Challenge 字段

| 字段 | 含义 |
|---|---|
| challenge_id | Challenge 引用 |
| purpose | REGISTER、PASSWORD_RESET、STEP_UP、CHANGE_IDENTIFIER |
| method | PHONE、EMAIL |
| normalized_target_ref | 目标不可逆引用 |
| user_id | 已知 User；匿名注册可为空 |
| challenge_state | CREATED、SENT、VERIFIED、EXPIRED、REVOKED、ATTEMPT_EXCEEDED |

## 20.11 配置和版本字段

以下配置必须保存版本引用，不能只覆盖当前值：

| 配置 | 关键字段 |
|---|---|
| Registration Policy | owner_limit、staff_limit、merchant_state_rules、policy_version |
| Password Policy | length、guessability、reuse、KDF 参数引用、first_change_rule、policy_version |
| Verification Policy | method、TTL、cooldown、max_attempts、rate_limit、strategy_version |
| Risk Policy | rule_id、weight、window、decay、threshold、hard_rule、risk_policy_version |
| Session Policy | sliding_ttl、rotation、device_binding、session_policy_version |
| Provider Config | provider_key、base_url 引用、credential_ref、headers 版本、provider_config_version |
| Agent Pricing | pricing_version、input_usd、output_usd、cached_input_usd、usd_to_points_version |

旧 Challenge、旧 Session、历史 Task 和 Model Call 必须继续引用创建时的版本；发布新版本不能重算历史事实。

## 20.12 字段级不变量

1. Stable Reference 不用手机号、邮箱、邀请码或 Token 代替。
2. 状态字段只能通过合法迁移改变。
3. Decision、Challenge、Session、Reset 和 Task 都能追溯 Policy、Strategy 或 Config Version。
4. 高风险写操作都有 Idempotency Key，或明确记录无需幂等的原因。
5. 并发命令都有 expected_version 或等价的原子条件。
6. 外部发送都有 Outbox Event 和 Retry 状态。
7. 密码、验证码、临时凭据、Token 和 API Key 不进入明文持久化。
8. Audit 能回答谁、对哪个对象、基于什么规则、做了什么、结果如何，但不泄露秘密。
9. Agent 积分 Ledger、USD 成本、Pricing Version 和 Settlement Reference 可以互相追溯。
10. TTL、限流数值、密码长度、阈值、KDF 参数和 Provider 属于配置，不冒充产品关系。

# 21. 08 的收口状态

完成本字段语义补充后，账户与身份模块可标记为：

~~~text
Status: DESIGN FROZEN v1
~~~

这表示业务流程、模块边界、六类核心决策、状态机、并发幂等、字段语义和版本追踪足以支撑领域模型、数据库 Schema、API 和编码。具体 TTL、限流数量、Argon2id 参数、短信/邮件供应商和运维阈值继续作为版本化实现配置。
