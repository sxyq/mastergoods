# 01 — 账户与身份模块

> 顶层模块文档  
> 负责用户账号、商户归属、注册、登录、会话、账号状态以及 Merchant Agent 积分账户。

# 1. 模块范围

```mermaid
flowchart TD
    A[账户与身份模块]

    A --> U[User Account]
    A --> M[Merchant]
    A --> MM[Merchant Membership]
    A --> R[Role]
    A --> INV[Invitation]
    A --> SESSION[Session / Token]
    A --> STATUS[Account Status]
    A --> POINT[Agent Point Account]
```

三个系统账号角色：

```text
SYSTEM_ADMIN
OWNER
STAFF
```

客户 / 供应商不是系统账号。

# 3. 核心关系

```mermaid
flowchart TD
    USER[User Account]

    USER --> SA[SYSTEM_ADMIN]
    USER --> MEMBERSHIP[Merchant Membership]

    MEMBERSHIP --> OWNER[OWNER]
    MEMBERSHIP --> STAFF[STAFF]

    MERCHANT[Merchant] --> MEMBERSHIP
    MERCHANT --> POINT[Agent Point Account]
```

SYSTEM_ADMIN：

```text
平台级身份
不依赖 Merchant Membership
```

OWNER / STAFF：

```text
User
+
Merchant Membership
+
Role
```

# 4. 注册总入口

```mermaid
sequenceDiagram
    actor SA as SYSTEM_ADMIN
    actor U as OWNER / STAFF
    participant INV as Invitation Service
    participant IAM as Identity Service
    participant DB as PostgreSQL

    SA->>INV: 创建邀请码并配置 OWNER / STAFF 配额
    INV->>DB: 保存邀请码

    U->>INV: 使用邀请码注册
    INV->>DB: 校验状态、配额、Merchant 绑定状态
    INV-->>IAM: Registration Admission

    IAM->>DB: 创建 / 关联 User 与 Membership
    IAM-->>U: 注册完成
```

# 5. 登录总入口

```mermaid
sequenceDiagram
    actor U as SYSTEM_ADMIN / OWNER / STAFF
    participant C as Client
    participant IAM as Identity Service
    participant DB as PostgreSQL

    U->>C: 登录
    C->>IAM: Authenticate
    IAM->>DB: 校验 User / Role / Membership / Merchant 状态
    DB-->>IAM: Identity Context
    IAM-->>C: Session / Token + Identity Context
```

iOS / Android 支持：

```text
30 天滑动 Token
+
App 再次打开自动登录
```

# 6. Agent 积分为什么属于账户模块

Agent 积分本质是 Merchant 在平台上的：

> **Agent Usage Credit Account**

它具备典型账户属性：

```text
balance
ledger
grant
consume
adjust
negative balance
recharge offset
status
```

因此它不是 Agent Runtime 的内部状态。

```mermaid
flowchart LR
    AGENT[Agent 模块] --> COST[计算 Task USD Cost]
    COST --> ACCOUNT[账户模块]
    ACCOUNT --> POINTS[USD → Points]
    POINTS --> BALANCE[Merchant Point Balance]
    BALANCE --> LEDGER[Point Ledger]
```

# 7. 当前冻结原则

1. 注册使用 SYSTEM_ADMIN 提供的邀请码；
2. 邀请码当前主规则最多注册 1 个 OWNER；
3. STAFF 注册数量由 SYSTEM_ADMIN 配置；
4. OWNER 首次注册后创建并绑定 Merchant；
5. STAFF 使用同一 Merchant 邀请码加入；
6. iOS / Android 使用 30 天滑动会话；
7. 每次手工登录或自动登录成功都刷新本地 Token；
8. 账号或 Membership 停用立即覆盖未过期 Token；
9. 历史业务记录继续保留原操作者；
10. Agent 积分账户归 Merchant；
11. 积分允许因已准入 Task 最终结算变为负数；
12. 后续充值先自然抵扣负余额；
13. Balance <= 0 时禁止开启新的 Agent Task。
