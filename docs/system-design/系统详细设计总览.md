# 1. 三个系统用户

```text
SYSTEM_ADMIN = 系统管理员
OWNER        = 店长
STAFF        = 店员
```

客户和供应商不属于系统账号。

```mermaid
flowchart TD
    ROOT[master-goods 系统用户]
    ROOT --> PLATFORM[平台侧]
    PLATFORM --> SA[SYSTEM_ADMIN 系统管理员]
    ROOT --> MERCHANT[商户侧]
    MERCHANT --> OWNER[OWNER 店长]
    MERCHANT --> STAFF[STAFF 店员]
```

其中：

- SYSTEM_ADMIN 是平台角色；
- OWNER 是一家 Merchant 的店长；
- STAFF 是一家 Merchant 的店员；
- **当前不支持 OWNER 多 Merchant，也不支持 STAFF 多 Merchant**；
- 一个 Merchant 当前只对应一个 OWNER；
- STAFF 数量由 SYSTEM_ADMIN 创建邀请码时设置的上限控制。

# 2. 客户端平台

当前平台目标不是 H5，而是：

```text
微信小程序
Android App
iOS App
Web
```

```mermaid
flowchart TD
    SA[SYSTEM_ADMIN]
    OWNER[OWNER]
    STAFF[STAFF]

    MINI[微信小程序]
    ANDROID[Android App]
    IOS[iOS App]
    WEB[Web]
    API[统一 Backend API]

    SA --> WEB
    OWNER --> MINI
    OWNER --> ANDROID
    OWNER --> IOS
    OWNER --> WEB
    STAFF --> MINI
    STAFF --> ANDROID
    STAFF --> IOS
    STAFF --> WEB

    MINI --> API
    ANDROID --> API
    IOS --> API
    WEB --> API
```

第一阶段：

- SYSTEM_ADMIN 主要使用 Web 管理后台；
- OWNER / STAFF 四端复用同一 Backend；
- 四端不复制业务规则；
- Agent 也是业务入口，不是第二套 Backend。

# 3. Backend 总体原则

```mermaid
flowchart TD
    UI[普通 UI]
    AGENT[Agent Tool]
    ADMIN[SYSTEM_ADMIN 管理操作]

    UI --> APP[Application Service]
    AGENT --> APP
    ADMIN --> ADMINAPP[Admin Application Service]
    ADMINAPP --> APP

    APP --> POLICY[Authorization / Feature Policy]
    POLICY --> DOMAIN[Domain Rules]
    DOMAIN --> DB[(PostgreSQL)]
    DOMAIN --> AUDIT[Audit / Revision]
```

核心原则：

1. 四端共用 Application Service；
2. Agent Tool 复用同一业务服务；
3. SYSTEM_ADMIN 也不能直接绕过 Domain 改数据库；
4. Merchant 是业务数据隔离边界；
5. 关键业务修改必须可追溯；
6. 收款 / 付款是记账，不是支付网关；
7. Feature Flag 关闭不能删除历史业务数据；
8. 第一阶段采用模块化单体，不提前拆微服务。

# 4. Merchant 数据范围

OWNER / STAFF 都只能访问自己唯一所属 Merchant。

```mermaid
sequenceDiagram
    actor U as OWNER / STAFF
    participant API as Backend API
    participant IAM as Identity Context
    participant AUTH as Authorization
    participant APP as Business Service

    U->>API: Request
    API->>IAM: Resolve User
    IAM-->>API: User + Merchant + Role

    API->>AUTH: Check Action
    AUTH-->>API: Allow / Deny

    API->>APP: Command with trusted Merchant Context
    APP-->>API: Result
    API-->>U: Result
```

服务端不能相信客户端自行传入任意 `merchant_id`。

SYSTEM_ADMIN 跨 Merchant 时，Merchant 是管理目标，不是 Membership。

# 7. Agent 与账户模块边界

```mermaid
sequenceDiagram
    participant TASK as Agent Task
    participant MODEL as Agent Model Billing
    participant ACCOUNT as Agent Point Account
    participant DB as PostgreSQL

    TASK->>MODEL: 多次 Model Call Usage
    MODEL->>MODEL: Token Usage -> USD Cost
    MODEL-->>TASK: Task Total USD

    TASK->>ACCOUNT: Settle Task USD
    ACCOUNT->>ACCOUNT: USD -> Agent Points
    ACCOUNT->>DB: Point Ledger + Balance
    ACCOUNT-->>TASK: Settlement Result
```

```text
Provider / Model / Token USD 定价
→ Agent 模块

Merchant Agent 积分余额 / 流水 / 负数 / 充值抵扣
→ 账户模块
```
