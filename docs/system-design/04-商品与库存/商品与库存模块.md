# 04 — 商品与库存模块

> 状态：商品默认售价维护业务边界已确认；其余详细业务仍待分析（PARTIAL BASELINE）
> 文档性质：顶层模块索引

统一分析商品资料和库存生命周期。产品层关注“商品是什么、多少钱、还有多少、为什么发生库存变化”，系统内部再设计库存变动、调整、盘点和低库存能力。

## 主要范围

- 商品基础资料、分类、单位、价格、条码等。
- 当前库存。
- 销售、采购、退货对库存的影响。
- 手工库存调整。
- 盘点。
- 低库存与库存变动查询。

销售和采购拥有各自交易规则，本模块不重复实现其业务生命周期。

---

## 2026-10-11 已确认：商品默认销售价维护

**系统定位**：面向单仓经营场景的进销存管理（采购入库、销售出库、库存、往来与记账）；无明确要求时不引入多仓价目和复杂零售促销。单仓是业务场景，并不等于物理表结构未来只允许一座仓库。

**产品已确认**：
1. OWNER（店长）可以设置、修改本 Merchant 商品的默认销售价；
2. STAFF（店员）也可以在本 Merchant 商品售价维护授权范围内设置、修改默认销售价，不能设计为只有店长有维护能力；
3. STAFF 改价后，OWNER 可以查看本商品**最新默认销售价及历史变更记录**，记录至少包含商品、适用单位、修改人、旧价、新价、时间和来源；
4. 商品默认价属于 Product 当前商户商品资料，更新会影响后续卖货默认带价；不静默改写已保存 SaleDraft，也不回写历史完成销售；
5. 商品默认售价修改**不是**本笔 SaleDraft 人工成交价修改；两条业务路径需要分开权限与审计。

### 主时序

~~~mermaid
sequenceDiagram
    actor U as OWNER/授权STAFF
    participant UI as 商品维护入口
    participant APP as ProductApplicationService
    participant POL as Merchant与权限策略
    participant DB as Product价格与版本
    participant LOG as 商品价格变更事实
    actor O as OWNER商品视图
    U->>UI: 输入商品默认销售价
    UI->>APP: UpdateDefaultPrice(product,unit,value,expected_version,idempotency_key)
    APP->>POL: 校验Merchant ACTIVE、Product归属、用户与STAFF授权、合法价格/单位
    alt 不通过
        APP-->>UI: 拒绝，当前价格不变
    else 通过
        APP->>DB: CAS更新当前价和版本
        APP->>LOG: 可靠保存前后价、修改人、时间与来源
        APP-->>UI: 返回成功及新价格
        O->>APP: 查询商品及价目历史
        APP-->>O: 看到店员设定的新价格及改动记录
    end
~~~

**图示说明**：修改 Product 当前价与必要变更记录应可靠一致，不能出现“价改成功但店长查不到修改者”；两名用户并发修改采用 Product 版本判定，网络重试幂等。FROZEN/CLOSED 禁止改价、只读按权限查询；不能跨 Merchant 修改或查看；Agent 按当前用户通过正常商品服务执行。

### 与销售模块的接口

~~~text
商品主档：OWNER/STAFF设置默认价 → 服务端保存当前价与历史 → OWNER查询可见
销售草稿：选择本店商品与单位 → 读取已提交默认价 → 保存本单快照 → 数量×成交价计算金额
商品改价后：新销售引用新价；旧草稿需提示差异，不静默改变；已完成交易金额不回写
~~~

### 仍需后续设计/确认

- STAFF 商品价格维护授权的默认开放范围、是否有主动消息推送；**可见不意味着必须审批或必须推送**；
- 商品尚无默认售价时能否通过本单临时报价销售（S-08 余项）；
- 商品单位与多单位默认价、精度、停售、修改历史保留期限；
- 商品完整建档、分类条码、库存、盘点、手工调整、流水、低库存和性能/审计体系仍需逐项详细设计。

本节只冻结用户明确的价格维护职责与店长可见性，**不代表整个 04 商品与库存已经设计完成**。
