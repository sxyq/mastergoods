# 02 — 销售 / 出库模块

> 状态：详细需求分析准备中
> 文档性质：顶层模块总览
> 设计体系：10 个业务子模块 + 1 个最终收口子模块

## 1. 模块目标

本模块覆盖“卖货 / 销售出库”的完整业务生命周期。销售不是单纯的一张单据，而是商品、价格、客户、收款、欠款、库存、更正、退货、权限和审计共同参与的一次经营事实记录。

├── 销售模块.md
├── 01-创建销售与商品明细.md
├── 02-数量单位价格与金额计算.md
├── 03-客户关联与赊账.md
├── 04-当次收款与结算.md

## 4. 与其他顶层模块的边界

- **01 账户与身份**：提供当前用户、Merchant、角色与权限上下文。
- **04 商品与库存**：拥有商品与通用库存生命周期；销售只定义本次交易应产生的库存影响。
- **05 往来与资金**：拥有外部往来对象、通用往来余额、记账账户和后续收付款；销售负责本次交易的客户关联、当次实收和由销售产生的欠款。
- **06 经营分析**：消费销售数据形成统计与分析。
- **07 Agent**：通过同一销售 Application Service 查询、生成草稿与确认执行，不复制销售业务规则。
- **08 平台管理与数据迁移**：SYSTEM_ADMIN 通过受控业务服务纠错和审计，Legacy 数据按迁移规则进入新销售模型。

## 5. 文档规则

后续对话可以相对简洁，但正式子模块文档必须遵循 `docs/system-design/文档编写规范.md`，至少完整记录：

1. 设计目标；
2. 角色与权限；
3. 业务实体 / 状态；
4. 主时序；
5. 分支与异常时序；
6. 状态迁移；
7. 一致性 / 事务；
8. 安全；
9. Audit；
10. 设计模式；
11. 判断算法；
12. 性能 / 索引 / 并发；
13. 边界条件；
14. 已冻结规则；
15. 待确认项。

未经用户确认的核心产品规则必须保持“讨论中 / 待确认”，不能由 Coding Agent 自行补齐。
