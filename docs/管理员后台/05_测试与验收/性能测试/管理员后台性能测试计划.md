## 一、指标与目标

| 指标 | 目标 | 采集方式 |
|---|---:|---|
| session 查询 p95 | ≤ 500 ms | API 计时 |
| 用户/门店列表 p95 | ≤ 1.0 s | 含过滤、排序、分页和 count |
| Agent 运行列表 p95 | ≤ 1.5 s | 含范围和状态过滤 |
| 运行详情首屏 p95 | ≤ 1.5 s | 摘要和首批事件，不含全文 |
| 平台总览 p95 | ≤ 3.0 s | 关键指标和趋势摘要 |
| 事件首批到达 | ≤ 1.0 s | SSE 或分页事件时间 |
| 5xx 比例 | 目标 < 1% | 按路由和角色统计 |
| 数据库扫描 | 接近 page/size | SQL/查询计划核对 |
| 单次响应体 | 按接口上限 | 排除未授权大字段 |

目标值是设计门槛，必须在指定环境实测后才能判断。

## 二、测试场景

| 用例 | 数据/负载 | 关注内容 | 通过条件 |
|---|---|---|---|
| `TEST-ADM-P01` 空数据 | 无用户、无运行、无事件 | 空状态和首屏 | 无异常等待，结果明确 |
| `TEST-ADM-P02` 小数据 | 单 owner、少量门店 | 基线延迟 | 达到接口目标 |
| `TEST-ADM-P03` 分页数据 | 多 owner、多门店、大量运行 | SQL 行数、p95、内存 | 数据库分页，无全量加载 |
| `TEST-ADM-P04` 长事件链 | 单 run 大量事件/大摘要 | 首屏和响应大小 | 摘要先返，事件分页 |
| `TEST-ADM-P05` 总览并发 | 多管理员同时查看 | CPU、连接池、DB | 不影响普通业务 API |
| `TEST-ADM-P06` 高频刷新 | 多面板周期刷新 | 请求数、缓存、渲染 | 无请求放大和旧数据覆盖 |
| `TEST-ADM-P07` 导出并发 | 多个异步导出任务 | 队列、存储、过期 | 任务隔离、可下载、可清理 |
| `TEST-ADM-P08` 事件断线 | 中途断开与恢复 | 补读、重复、资源 | 不重复渲染，终态完整 |
| `TEST-ADM-P09` 越权流量 | 大量非法范围请求 | 拒绝延迟和审计 | 全部拒绝，不命中错误缓存 |
| `TEST-ADM-P10` PostgreSQL 计划 | 目标数据库真实数据 | `EXPLAIN`/`EXPLAIN ANALYZE` | 有真实 PostgreSQL 才执行，否则阻塞/延期 |

## 三、资源指标

采集 API p50/p95/p99、JVM CPU/堆内存、线程池、数据库连接池、查询耗时/扫描行数、响应大小、SSE 连接数、导出队列、磁盘临时空间和审计写入失败数。记录测试数据量和并发模型，不能只给平均值。

## 四、性能边界

- 不把增加内存或前端分页当作数据库分页修复。
- 不用 H2 或 SQLite 的查询计划替代目标 PostgreSQL 结论。
- 长正文、工具结果和审计 payload 不进入列表接口。
- 单个面板慢或失败时不能阻塞其他面板。
- 事件流客户端断线不应创建无限重连和请求堆积。

## 五、证据

保存压测参数、数据规模、命令输出、API 计时、数据库计划、资源快照和清理结果；敏感字段只保留字段名或脱敏摘要。建议目录：`testing/.artifacts/<日期>-admin-performance/`。
