## 二、界面语义

管理员后台表达的是“观察、追踪、核验和受控管理”，页面语义按以下层级组织：

1. **平台状态**：先回答系统是否正常、用户/门店规模和 Agent 使用量。
2. **运行事实**：再回答某次运行由谁发起、属于哪个 owner/store、调用了哪些工具、花费多少 Token、最终处于什么状态。
3. **证据链**：最后展开消息、SSE 事件、工具结果、上下文检查点、草稿和审计事件。
4. **受控动作**：配置、账号状态、权限和导出必须显著区别于只读查看，并说明影响范围。

页面不把装饰性图形当作业务结论。图表必须带标题、时间范围、单位、空数据状态和可读摘要；颜色只作为辅助，状态文字和图标同时出现。

## 三、视觉规则

| 维度 | 规则 |
|---|---|
| 背景 | 近白页面背景，白色导航和内容面板，避免大面积渐变 |
| 侧栏 | 桌面端约 288px 固定侧栏；移动端改为覆盖式导航 |
| 内容宽度 | 以约 1280px 为舒适阅读上限，宽屏保留呼吸空间 |
| 面板 | 约 8px 圆角、细灰边框、轻微阴影；面板之间保持统一间距 |
| 主色 | 深色文字和深色主按钮；危险操作使用明确警示色 |
| 辅助色 | 蓝色表示信息，绿色表示成功，紫色表示上下文/工具域，琥珀色表示关注 |
| 字体 | 系统无衬线字体；数字使用清晰的等宽或数字友好字形 |
| 图标 | Lucide 风格线性图标，图标和文字共同表达，不使用无语义装饰图标 |
| 表格 | 任务列突出，用户/门店和工具使用次级层级，Token 与耗时右对齐 |
| 状态 | `已完成`、`待确认`、`需关注`、`失败`、`进行中`使用标签和文本 |
| 动效 | 只用于抽屉、加载、刷新和实时状态变化，不能让数据变化难以追踪 |

## 五、页面与图表实施契约

| 页面 | 主要区域 | 图表/可视化 |
|---|---|---|
| 平台总览 | 指标、趋势、运行状态、最近运行、最近审计 | 日运行趋势、终态完成率环、每次运行工具调用量 |
| 用户与门店 | 用户列表、门店列表、成员关系、状态和最近登录 | 用户总数与门店总数对比条形摘要 |
| Agent 运行 | 运行表、运行详情、事件时间线、Token 和耗时 | 按模型的 Token/耗时趋势、事件时间线 |
| Agent 配置 | 模型 ID、工具目录、启用范围、版本和生效时间 | 当前配置状态与单个生效时间；历史时间线等待后端历史接口 |
| 操作审计 | 审计筛选、事件表、详情和导出 | 表格是主证据；可显示当前加载结果页的动作计数，不能表示完整时间范围分布 |
| 系统状态 | 健康状态、版本、错误摘要、数据保留 | 服务状态卡与按发生时间排列的错误摘要；没有历史序列时不绘制趋势线 |

### 5.1 图表数据口径

| 可视化 | 数据接口与字段 | 统计口径 | 交互与降级 |
|---|---|---|---|
| 日运行趋势 | `GET /v2/admin/overview` 的 `trend[].at`、`trend[].value` | 后端按请求时间范围逐日计算 Agent 运行数；前端不能二次合并成其他时间口径 | 时间范围固定为 7、30、90 天；显示总运行数、最高单日值和日期/数值表格文本；空数据展示明确空态 |
| 终态完成率环 | `metrics[key=agent_success_rate]` | `completed / terminalRuns * 100`，无终态样本时服务端返回 `UNAVAILABLE` | 环中心保留百分比文本；不可用时显示“暂无”，不以 0% 代替 |
| 每次运行工具调用量 | `metrics[key=agent_tool_calls]`、`metrics[key=agent_runs]` | `agent_tool_calls / agent_runs`，仅在运行数大于 0 时计算 | 与工具调用总量同时展示；缺少分母时显示“暂无”，不会输出工具域分布 |
| 用户与门店规模摘要 | `GET /v2/admin/users`、`GET /v2/admin/stores` 的 `total` | 已授权范围内的用户总数与门店总数 | 使用并列条形和直接数字；状态分布只能针对当前加载结果页，并标明范围 |
| Agent Token/耗时趋势 | `GET /v2/admin/agent/usage` 的 `bucket_start`、`bucket_end`、`input_tokens`、`output_tokens`、`total_tokens`、`average_duration_ms`、`p95_duration_ms`、`token_source` | 以服务端 bucket 为单位；模型混合时按模型分组或要求先选择模型，估算数据须带 `ESTIMATED` 标识 | 默认显示 Token 总量，切换到耗时；每个关键值有文本摘要，空 bucket 不用前次数据填充 |
| 运行事件时间线 | `GET /v2/admin/agent/runs/{runId}/events` 的 `sequence`、`event_type`、`occurred_at`、`status`、`duration_ms` | 事件按 `sequence` 排列，真实时间仅用于辅助显示 | 运行中可从 SSE 按最后序号续读；缺失或乱序显示完整性提示，终态后停止连接 |
| 审计动作摘要 | `GET /v2/admin/audit/events` 的当前页 `items[].action` | 仅统计当前加载的结果页，不代表完整筛选结果 | 以“当前页”标签和总记录数并列显示；没有聚合接口时表格保持主视图 |
| 系统错误摘要 | `GET /v2/admin/system/health` 的 `errors[].occurred_at`、`category`、`summary` | 当前健康响应中的最近错误摘要，非持续历史监控 | 按时间排序成时间线；服务端提供历史聚合后才可增加趋势图 |

图表统一使用语义化 SVG 或普通 DOM 区域，不依赖悬浮才可读取关键数值。每个区域必须提供标题、统计范围、单位、直接数值、加载、空数据、局部失败和部分范围提示。颜色用于增强区分，状态文本和图标同时保留。

## 六、关键交互状态

| 状态 | 页面表达 | 行为 |
|---|---|---|
| 加载中 | 面板内骨架或明确加载标识 | 关键指标和其他面板可以独立加载 |
| 空数据 | 图标、说明、时间范围和清除筛选入口 | 不显示上一次查询的旧数据 |
| 局部失败 | 面板错误说明、request ID 类摘要、重试按钮 | 只重试失败面板 |
| 运行中 | 状态标签、事件流指示和最近更新时间 | 允许刷新/断线重连，不把未结束运行标记为完成 |
| 工具失败 | 失败图标、工具名、错误类别和时间 | 显示后续是否继续或终止 |
| 草稿待确认 | 明确“等待用户确认”标签 | 管理员只能查看，不替用户确认 |
| 越权 | 受控错误页或空范围说明 | 服务端返回拒绝，页面不猜测资源存在 |
| 高风险写操作 | 影响范围、旧值/新值、原因和二次确认 | 确认后才调用 API，结果进入审计 |
| 脱敏 | “部分内容已隐藏”提示和原因类别 | 可按内容权限重新授权，不显示秘密字段 |
