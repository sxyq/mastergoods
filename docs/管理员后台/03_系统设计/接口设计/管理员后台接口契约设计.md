## 一、契约原则

1. 每个请求先解析管理员身份，再校验动作权限和 owner/store 范围。
2. 列表响应只返回当前页面，不能返回全量数据后让前端分页。
3. 所有资源 ID 在 JSON 中使用字符串；时间使用带时区的 ISO 8601。
4. 查询失败、无权限、资源不可见、版本冲突和下游错误使用稳定状态码和错误码。
5. 运行详情按摘要、消息、事件、草稿、上下文拆分加载，控制响应体大小。
6. 正文、参数和结果必须经过内容权限与脱敏处理；认证敏感字段不进入 DTO。

## 三、列表参数

| 参数 | 类型 | 默认/限制 | 说明 |
|---|---|---|---|
| `page` | integer | 0 | 从 0 开始；当前 `PaginationUtils` 将负数归零 |
| `size` | integer | 50，最大 200 | 小于等于 0 使用默认值，超过 200 截断 |
| `sort` | enum | 接口默认字段 | 仅白名单字段 |
| `direction` | enum | `desc` | 仅 `asc`/`desc` |
| `ownerUserId` | string | 空表示授权范围 | 先校验范围再查询 |
| `storeId` | string | 空表示 owner 下全部门店 | 校验 owner/store 关系 |
| `from`、`to` | datetime | 由接口规定最大窗口 | 必须满足时间顺序 |
| `cursor` | string | 当前未暴露 | 事件列表使用 `afterSequence`，不能把 cursor 语义写入当前接口 |

## 四、Agent 运行 DTO

### 4.1 运行摘要

```text
AdminAgentRunSummary
  runId: string
  conversationId: string|null
  actorUserId: string|null
  ownerUserId: string
  storeId: string|null
  terminalStatus: enum
  modelId: string|null
  startedAt: datetime
  completedAt: datetime|null
  durationMs: long|null
  timeToFirstTokenMs: long|null
  iterationCount: integer|null
  toolCallCount: integer|null
  inputTokens: integer|null
  outputTokens: integer|null
  totalTokens: integer|null
  tokenSource: EXACT|ESTIMATED|UNAVAILABLE
  contentRedacted: boolean
```

`actorUserId` 或 `storeId` 无可靠来源时返回 `null`，同时返回 `scopeCompleteness`，页面不得根据 owner 名称猜测门店或发起者。

### 4.2 工具事件

```text
AdminAgentEvent
  eventId: string
  runId: string
  sequence: integer
  eventType: enum
  toolName: string|null
  callId: string|null
  occurredAt: datetime
  status: STARTED|PROGRESS|COMPLETED|FAILED|CANCELLED
  durationMs: long|null
  argumentSummary: string|null
  resultSummary: string|null
  redactionState: FULL_ALLOWED|PARTIAL|REDACTED
```

`plan.delta` 只能作为计划摘要；只有 `tool.started` 及之后的事件才能作为实际调用事实。重复序号和缺失序号必须通过 `eventIntegrity` 字段提示。

## 五、SSE 观测契约

管理员实时查看不是重新执行 Agent。服务端从持久化事件或可靠事件总线读取，并支持：

- `Last-Event-ID` 或 `afterSequence` 补读。
- 事件按 `sequence` 顺序发送，重复事件由客户端去重。
- 发送 `run.completed`、`run.failed`、`run.cancelled` 或 `run.exhausted` 后结束流。
- 断线不改变运行，客户端可以重新请求事件列表。
- 正文和工具参数的权限在每个详情请求中重新校验。
- 事件流中不返回 Cookie、Session Token、密码、Provider 密钥、私钥或完整认证载荷。

## 六、写接口

所有 PATCH/POST 写接口至少需要：

```text
idempotencyKey: string
expectedVersion: long
reason: string
scope: { ownerUserId?: string, storeId?: string }
```

服务端必须忽略客户端试图扩大 scope 的字段；`expectedVersion` 冲突返回 `409`；同一幂等键和同一 payload 返回原结果；同一幂等键和不同 payload 返回明确冲突。

## 七、错误响应

```json
{
  "success": false,
  "error": {
    "code": "ADMIN_SCOPE_DENIED",
    "message": "当前账号无权访问该范围",
    "fieldErrors": [],
    "requestId": "request-example"
  }
}
```

示例中的 ID 只是占位值。错误消息面向用户，不包含 SQL、连接字符串、堆栈、密钥或完整请求内容。

## 八、契约验收

| 项目 | 验收条件 |
|---|---|
| 认证 | 无会话返回 401，响应结构稳定 |
| 权限 | 观察员写操作返回 403，不执行 Repository 写入 |
| 范围 | 跨 owner/store 不能读取或通过缓存命中 |
| 分页 | `page/size/sort` 有边界和稳定排序 |
| Agent | run、conversation、event、draft、context 关联可追踪 |
| SSE | 顺序、补读、去重、终态和断线有测试 |
| 脱敏 | 凭据字段永不出现在响应、日志、导出 |
| 写操作 | 版本、幂等、事务和审计都可断言 |
