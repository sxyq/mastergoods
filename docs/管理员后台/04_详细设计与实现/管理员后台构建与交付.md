## 三、提交边界

- 后端、Web、数据库、测试和文档按功能拆分提交。
- 提交前检查文件列表和差异，不把 `data/`、凭据、构建产物和其他用户修改带入。
- 不执行生产部署、迁移或 `git push`，除非得到单独授权。
- 任何配置变更都要说明环境、作用范围和恢复方式。

## 四、发布前门槛

1. 两类管理员的登录、权限和范围测试通过。
2. Agent 运行详情可以关联实际运行、消息、工具、草稿、上下文和审计。
3. Token 和耗时统计有明确来源；估算值有标记。
4. 跨 owner/store 查询和观察员写入测试全部拒绝。
5. Provider 密钥、会话凭据和密码未出现在代码、响应、日志和导出。
6. PostgreSQL 查询计划在目标数据库上完成；没有环境则标记 `阻塞`。
7. Web build、后端测试、迁移测试和必要的安全测试有可追溯证据。
