## 一、通用接口规则

| 项目 | 规则 |
|---|---|
| 认证 | 使用现有统一会话机制；管理员角色和范围由服务端解析 |
| 方法 | 查询使用 `GET`；状态/配置变化使用 `PATCH` 或 `POST`；导出使用异步 `POST` |
| ID | JSON 中以字符串传输大 ID，避免 Web 精度丢失 |
| 分页 | `page >= 0`，`1 <= size <= 200`；默认稳定排序；响应返回 `page`、`size`、`total`、`items` |
| 时间 | `from`、`to` 为 ISO 8601；服务端明确时区并返回 `generatedAt` |
| 范围 | `ownerUserId`、`storeId` 只是筛选条件；服务端先校验管理员授权范围 |
| 幂等 | 所有配置和导出创建请求支持请求级幂等键；重复请求返回同一结果 |
| 错误 | 统一映射 `400` 参数错误、`401` 未认证、`403` 无权限、`404` 资源不可见或不存在、`409` 状态/版本冲突、`422` 业务校验失败、`429` 限流、`5xx` 下游故障 |
| 敏感字段 | 密码、Cookie、Session Token、Provider 密钥、私钥和完整认证载荷不出现在任何响应、日志或导出 |

| 编号 | 方法与路径 | 作用 | 角色 |
|---|---|---|---|

| API-ADM-03 | `GET/PATCH /v2/admin/users` | 用户列表、详情与状态管理 | 读：两类；写：超级管理员 |
| API-ADM-04 | `GET/PATCH /v2/admin/stores` | 门店列表、详情与成员关系 | 读：两类；写：超级管理员 |
| API-ADM-05 | `GET /v2/admin/agent/runs` | Agent 运行分页查询 | 两类 |
| API-ADM-06 | `GET /v2/admin/agent/conversations/{conversationId}/messages` | 会话消息分页查询 | 按内容权限 |
| API-ADM-07 | `GET /v2/admin/agent/runs/{runId}/events` | 工具与 SSE 事件时间线 | 两类 |

## 三、请求字段

### 3.1 通用查询字段

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `page` | integer | 否 | 大于等于 0，默认 0 |
| `size` | integer | 否 | 1–200，超限返回 `422` 或按项目规范截断 |
| `sort` | string | 否 | 只能使用服务端白名单字段 |
| `direction` | string | 否 | `asc` 或 `desc` |
| `ownerUserId` | string | 否 | 先校验授权范围 |
| `storeId` | string | 否 | 校验 store 与 owner 关系 |
| `from`、`to` | datetime | 否 | `from < to`，最大查询窗口由接口规定 |
| `query` | string | 否 | 长度受限，按字段白名单搜索 |

### 3.2 运行查询字段

| 字段 | 类型 | 用途 |
|---|---|---|
| `runId` | string | 精确查询一次运行 |
| `conversationId` | string | 查询会话关联运行 |
| `actorUserId` | string | 查询实际发起者 |
| `terminalStatus` | enum | `COMPLETED`、`FAILED`、`CANCELLED`、`EXHAUSTED` 等 |
| `toolName` | string | 按注册工具名筛选 |
| `modelId` | string | 按模型快照筛选 |
| `includeContent` | boolean | 需要额外内容权限，默认 `false` |

### 3.3 配置写入字段

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `idempotencyKey` | string | 是 | 长度、字符集和有效期按现有规范 |
| `expectedVersion` | long | 是 | 防止覆盖其他管理员刚提交的变更 |
| `modelId` | string | 视操作 | 只允许配置白名单模型 ID |
| `toolName` | string | 视操作 | 必须存在于 ToolRegistry |
| `enabled` | boolean | 视操作 | 只能改变允许范围内的开关 |
| `scope` | object | 否 | owner/store 适用范围，服务端再次过滤 |
| `reason` | string | 是 | 变更原因，长度受限，不得包含凭据 |

## 四、响应结构

### 4.1 列表响应

```json
{
  "success": true,
  "data": {
    "items": [],
    "page": 0,
    "size": 50,
    "total": 0,
    "hasNext": false,
    "generatedAt": "2026-08-28T00:00:00+08:00",
    "scope": {
      "ownerUserIds": [],
      "storeIds": []
    }
  }
}
```

示例只展示结构，不包含真实账号、凭据或业务内容。若响应被脱敏，应返回 `contentRedacted: true` 和脱敏原因类别，不返回原始敏感值。

### 4.2 Agent 运行详情

```json
{

  "conversationId": "conversation-example",
  "actorUserId": "user-example",
  "ownerUserId": "owner-example",
  "storeId": "store-example",

  "terminalStatus": "COMPLETED",
```

### 4.3 工具事件

每个事件至少返回：`eventId`、`runId`、`sequence`、`eventType`、`toolName`、`callId`、`occurredAt`、`status`、`durationMs`、`argumentSummary`、`resultSummary`、`redactionState`。原始参数和结果采用字段白名单，并限制长度。

事件类型与事实含义：

| 事件 | 含义 |
|---|---|
| `run.started` | 服务接受一次运行 |
| `plan.delta` | 计划摘要增量，不等于工具已执行 |
| `tool.started` | 统一执行门已通过并开始调用工具 |
| `tool.progress` | 工具报告进度 |
| `tool.completed` | 工具返回成功结果 |
| `tool.failed` | 工具返回失败、超时或被拒绝 |
| `context.compacted` | 服务端生成上下文检查点并完成压缩 |
| `draft.created` | 创建类工具只生成草稿 |
| `answer.completed` | 正式回答已经生成 |
| `run.completed` | 运行进入明确终态 |

## 五、数据一致性要求

| 要求 | 说明 |
|---|---|
| 运行关联 | `runId`、`conversationId`、`actorUserId`、`ownerUserId`、`storeId` 要能相互追踪 |
| 工具配对 | `assistant tool call` 与 `tool result` 通过 `callId` 配对；缺失一侧要标记不完整 |
| Token 总量 | 有精确 Provider 用量时 `totalTokens = input + output`；估算时必须标记来源 |
| 终态一致 | `run.completed` 与运行主记录终态一致；取消和失败不能显示为完成 |
| 草稿边界 | `draft.created` 不得自动产生正式业务表数据；确认事件后才允许业务写入 |
| 范围一致 | 详情接口再次校验范围，不能仅依赖列表接口传来的归属字段 |
| 审计失败 | 审计写入失败要有可观测错误和明确策略，不能静默假装记录成功 |

## 六、数据质量与空值

- 未结束运行的 `completedAt`、`durationMs`、最终 Token 可以为 `null`，页面必须显示“进行中”或“未生成”。
- Provider 未返回用量时，服务端可以使用统一估算器，但必须返回 `estimated=true` 和估算版本。
- 删除或脱敏后的消息仍保留关联 ID、角色、时间和状态，便于审计链路判断是否完整。
- 统计接口面对没有数据的范围返回空数组和零值，不复用上一次成功响应。
