# Android data/sync 模块分析

- 对应源码目录：`master-goods-android/data/sync`
- 关键源码：`SyncRepository.kt`

## 模块定位

新版里 `data/sync` 不再只是“定期 pull/upload”的技术模块，它还要变成：

- owner 私有同步基线的承载层
- 旧数据导入任务的客户端协调层
- 本地缓存与服务端聚合状态之间的桥接层

## 当前实现

- 已有健康检查、手动同步、pull 结果应用、游标持久化
- 已能把部分实体类型写回 Room
- 后台自动同步、离线回写、导入上送尚未完成

## 状态表

| 对象 | 状态 | 旧版情况 | 新版目标 | 当前实现 | 备注 |
|---|---|---|---|---|---|
| 基础手动同步 | 新版已做 | 旧版主要是本地账本 | 支撑在线优先架构 | `SyncRepository.kt` 已实现基础能力 | 能执行健康检查与 pull |
| `/v2` 同步与导入契约 | 新版待做 | 旧版无统一 server import 方案 | 把导入、增量同步、owner 分桶设计清楚 | 当前文档层面已规划，代码未动 | 本阶段只做文档 |
| owner 分桶游标 | 需重构 | 旧版无统一 owner | 游标与同步状态按 owner 隔离 | 当前主要是全局 cursor 语义 | 与 server `sync_cursors` 重构对应 |
| 只同步部分实体类型的思路 | 新版需要去掉 | 首版范围较窄 | 新版同步要覆盖扩域后的核心实体 | 当前实现仍偏首版范围 | 与 server `SyncService` 一起重构 |

## 导入链路规划

| 环节 | 状态 | 说明 |
|---|---|---|
| 客户端发起导入任务 | 新版待做 | 安卓提交 owner 归属的导入请求 |
| 导入任务轮询/订阅 | 新版待做 | 安卓显示服务端处理状态、冲突、完成度 |
| 本地缓存回填 | 新版待做 | 导入完成后按 owner 拉回数据 |
| 本地导入失败恢复 | 待验证 | 是否需要本地断点与补偿，后续再定 |

## 当前结论

- `data/sync` 已经具备“首版同步工具层”雏形。
- 但新版里，它会直接参与账号私有导入和 owner 私有同步，这意味着职责会明显增大。
