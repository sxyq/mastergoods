## 一、状态定义

| 状态 | 含义 | 举例（当前项目） |
|---|---|---|
| 已完成 | 当前源码、测试和证据可以互相对应 | 后端 Wave 0 环境/provenance/Provider 直连；Android 本地构建与单元测试 |
| 进行中 | 当前已有部分实现，仍存在明确开发内容 | 后端部分接口仅 V1 或 V2 单版本实现，未全部迁移 |
| 待验证 | 代码可能存在，但缺少当前运行证据 | iOS / Web 各页面存在源码，但本轮测试未展开 Agent 主流程 |
| Blocked | 前置设备、权限、数据或环境缺失 | Android 真机（无 adb）；8220 生产 Agent 业务链路（无 session/store/Agent 数据） |
| Deferred | 当前明确暂缓，不阻塞其他范围 | 多模态、生图、图片输入和图片结果展示 |
| Failed | 已执行且结果不满足要求 | 已知问题清单中的失败项（见 `07_问题审计/当前已知问题.md`） |
| historical-only | 旧服务器、旧版本或旧测试资料 | 154 服务器全部内容、旧 154 测试证据、退役前运行快照 |

## 二、状态与证据的对应规则

1. 状态为 `已完成` 的结论，必须同时满足：
   - 当前源码中存在对应实现；
   - 存在可执行的测试计划或已执行测试；
   - 存在当前环境的真实证据（8220 基线、SSE 原始文件、构建日志等）。
2. 状态为 `待验证` 的结论，必须在文档中说明缺少哪一类证据（例如"缺少 8220 运行证据"）。
3. `Blocked` 必须说明阻塞原因（设备、权限、数据或环境）。
4. `Deferred` 必须说明暂缓原因和恢复条件。
5. `historical-only` 内容不得参与当前通过率、发布验收或运行状态判断。

## 四、历史状态不回写规则

- 154 的历史数据（users=5、sessions=5、stores=1、agent_conversations=18 等）是 154 历史 baseline，不得回写成当前 8220 结果。
- 旧设备（如 `d715a3a4` 在 154 环境）上的测试结果不能作为当前 8220 真机证据。
- 旧 154 探针结果（如 `function_call_output` HTTP 400）不能直接套用到当前 8220 Provider。
- 当前 8220 业务主表为空：products、customers、suppliers、sale_orders、purchase_orders、finance_records、inventory_snapshots、inventory_ledger、accounts、payments、media_assets。

来源：`testing/README.md`（"Execution Start Baseline"与"Current 8220 Baseline"一节）。

## 五、如何更新本文档

每当一轮测试 Wave 完成或基线变化时：

1. 先更新 `testing/README.md` 与 `testing/.artifacts/2026-08-18-8220-current-baseline/current-8220-baseline.md`。
2. 再回填 `testing/current-8220-wave-ledger.csv` 台账。
3. 最后更新受影响文档的状态字段与本节总表。
