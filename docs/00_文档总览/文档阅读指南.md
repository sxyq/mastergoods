## 二、每篇文档的固定格式

### 开头：文档信息表

| 字段 | 含义 |
|---|---|
| 文档类型 | 业务需求 / 业务系统需求 / 系统设计 / 实现说明 / 测试验收 / 运维 |
| 当前状态 | 已完成 / 进行中 / 待验证 / Blocked / Deferred / historical-only |
| 适用端 | 后端 / Android / iOS / Web / Agent / 多端 |
| 依据源码 | 该文档结论对应的真实源码路径 |
| 依据测试 | 该文档结论对应的测试计划或测试文件 |
| 依据证据 | 该文档结论对应的真实证据路径 |
| 最后核对 | 实际核对日期 |

### 结尾：对应关系与限制

每篇文档结尾必须包含"对应实现、对应接口、对应测试、当前限制"四个小节，把正文中的结论与真实代码、接口、测试和限制状态一一对应。

## 三、状态含义

| 状态 | 含义 |
|---|---|
| 已完成 | 当前源码、测试和证据可以互相对应 |
| 进行中 | 当前已有部分实现，仍存在明确开发内容 |
| 待验证 | 代码可能存在，但缺少当前运行证据 |
| Blocked | 前置设备、权限、数据或环境缺失 |
| Deferred | 当前明确暂缓，不阻塞其他范围 |
| Failed | 已执行且结果不满足要求 |
| historical-only | 旧服务器、旧版本或旧测试资料 |

## 四、证据规则

所有重要结论必须包含真实来源，格式为：

```text
源码：
接口：
测试：
证据：
当前环境：
核对日期：
```

可以使用的证据类型：

- Java / Kotlin / Swift / Vue 源码
- JUnit 测试、Android 单元测试
- Web / iOS 构建结果
- TEST_PLAN.md、CSV 测试台账
- 当前 8220 基线文件
- SSE 原始文件、JSON、UI XML、截图、logcat、性能报告

不能单独证明业务完成的证据：

- HTTP 200
- 编译通过
- README 中的描述
- 页面存在
- 静态占位图表
- 旧 154 测试结果
- 未找到源码后的经验推断
