## 1. 项目用途

## 6. 全部发现的问题（19 条可执行问题；问题台账另含 P-020 正面确认）

### P1（1 条）
- **P-001 销售订单核心金额使用 double**：`SaleOrderService` L68-99/L211-247/L249-292/L343-392——小计累加、数量×单价、客户余额增减均为 double。Android 相关模型和报表逻辑主要使用 `Double`，Web API 模型主要使用 `number`；表单中的字符串主要用于输入/展示，并不等于 BigDecimal 运算。可信度高，需运行时验证漂移。

### P2（9 条）
- **P-002** local profile 下仅 `/v1/admin/**` 对未认证请求放行；`AdminController`、`AdminService` 也仅在 local profile 注册，不能扩展成整个管理员接口面。
- **P-003** 邀请码分支充当验证码且 README 明文公开；源码默认配置为空，不能仅凭 README 确认运行环境当前值（AuthService L135-176 + README L141）。
- **P-004** 收款读取订单主表无锁，并发可能产生重复收款记录与 `paidAmount` 不一致；下单 L71 锁的是商品库存行，不是销售订单行。
- **P-005** 取消读取订单主表无锁；商品库存行虽在 L353 使用锁，但并发双取消仍可能双倍回补库存并重复写入 `AUTO-REFUND`（L343-392）。
- **P-006** 已完成订单可改折扣/总额且不校验已付额（updateDraft L211-247），需产品确认。
- **P-007** StorePermissionInterceptor 存在 fail-open 分支：缺 Authorization 头或 Bean 缺失时直接放行（L24-42）；这证明纵深不足，不能单凭此断定普遍匿名绕过。
- **P-008** `.ssh-check/` 当前核对到 7 个 PEM RSA 私钥文件（已被 gitignore 排除但仍在项目根；未读取内容）。
- **P-009** 会话缓存/黑名单 4 个 ConcurrentHashMap 没有定时清理，过期条目主要在再次查询时才移除（SessionAccessService）。
- **P-010** v1/v2 订单服务双轨维护；v1 无 DRAFT→CONFIRMED 路径，但 v1 仍被 Android 和 Web 多组接口使用，不能直接安排退出。

## 8. 调用关系与跨文件影响（18 条关键链路，详见《调用关系台账.csv》）

- **认证链**：Android AuthInterceptor/TokenAuthenticator → `/v1/auth/*` → AuthService → SessionAccessService（30s 缓存+黑名单）→ SessionRepository；TokenAuthenticationFilter 每请求还原 SecurityContext。
- **多租户链**：CurrentOwnerService.requireCurrentOwnerUserId（SecurityContext → StoreMembership；无 membership 默认 OWNER）→ 全部业务 Repository 的 ownerUserId 参数。
- **资金链**：下单（锁商品库存行并累加客户余额）→ 收款（订单主表无锁，P-004）→ 取消（订单主表无锁、商品行回补并写入 AUTO-REFUND，P-005）→ 报表（统一排除 CANCELLED、处理 REFUND，口径一致）。
- **Agent 链**：V2AgentChatStream（SSE）→ 工具/草稿 → AgentDraftConfirmService（CAS 防并发确认）→ 各业务 Service.create；审计经 AdminAuditService。
- **演示链**：DemoDataService.seed（@Profile("local")）→ 全库播种/清空。
- 跨文件影响最大的修改面：**金额类型改造（P-001）会波及实体、DTO、三端展示与报表口径**；**收款/取消并发处理（P-004/P-005）还需要统一订单、商品和客户的加锁顺序，并补充支付与退款幂等验证，不能只替换 Repository 方法**。
