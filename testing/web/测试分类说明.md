# Web 测试分类说明

## 使用原则

Web 测试先查看 `测试分类总台账.csv`，再根据对应类别的 `TEST_PLAN.md` 执行。每条页面、组件、函数、接口契约和安全场景记录都必须带 `category_id` 与 `category_name`。

## 分类范围

| 分类 | category_id | 覆盖范围 |
| --- | --- | --- |
| 功能测试 | WEB-FT | 路由、页面、按钮、表单、Agent 交互及错误状态 |
| 单元测试 | WEB-UT | 工具函数、Store、解析器、适配器和页面派生状态 |
| 性能测试 | WEB-PT | 页面加载、路由切换、大列表、图表和 Agent 流式渲染 |
| 审计 | WEB-AU | 组件职责、权限边界、输入输出、依赖和可维护性审查 |
| 破坏性逆向安全测试 | WEB-RST | 前端篡改、请求重放、上传绕过和服务端边界验证 |

## 统一记录字段

执行材料至少使用以下字段：

- `test_id`
- `category_id`
- `category_name`
- 环境、账号/store 和前置状态
- 操作、预期和实际结果
- 证据路径
- 清理动作
- `result`

结果值只使用 `Passed`、`Failed`、`Blocked`、`Deferred`。当前文件只描述规划，不代表任何测试已经执行。
