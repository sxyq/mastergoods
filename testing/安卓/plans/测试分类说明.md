# 安卓测试分类说明

## 使用原则

这份文件只定义安卓端测试规划分类；当前不保留执行台账、测试结果或脚本。

执行顺序：

1. 先看 `../README.md`，确认规划入口。
2. 再进入 `functional` / `unit` / `performance` / `security` 的规划文档。
3. 执行时按端根目录的测试类别目录保存材料。

## 分类范围

安卓测试规划目前覆盖：

- 单元测试 13 类
- 功能测试 14 类
- 性能测试 11 类

分类本身仍按原来的模块职责划分：

- 单元测试：工具、序列化、网络、DataStore、安全存储、Room、Repository、ViewModel、Compose、导航、安全守卫
- 功能测试：认证、首页权限、商品、客户、供应商、销售、采购、财务、报表、同步、Agent、设置安全
- 性能测试：启动、首页、大列表、Room、同步、Agent 首响应、Agent 长流、图片上传、状态风暴、长会话

规划分类以本文件和各测试类型的 `TEST_PLAN.md` 为准；当前未保留函数台账、结果矩阵或执行记录。

## 执行材料规则

执行记录、日志、脚本和原始证据不放入规划目录；按测试类型存放在端根目录对应的 `reports`、`logs`、`artifacts` 和 `scripts` 空目录中。每条记录的字段和状态以 Agent 综合测试方案为准。
