# Agent 测试分类说明

## 使用原则

Agent 是跨端专项，必须同时看：

1. `测试分类总台账.csv`
2. 各测试 lane 的函数级或场景级台账
3. 各端源码真实分布

当前这份说明文档只负责解释分类方式与字段语义。精确到文件和函数的真源，以 `测试分类总台账.csv` 和三个带 `category_id` 的台账为准。

  - 管理/演示支撑

  - 界面渲染与结果块

- iOS：3 类

## 统一台账字段说明

`测试分类总台账.csv` 当前字段：

- `test_type`: `单元测试` / `功能测试` / `性能测试`
- `category_id`: 稳定分类编号
- `category_name`: 分类名称
- `primary_scope`: 该分类的主对象或主链路
- `must_cover`: 分类下必须覆盖的能力点
- `evidence_standard`: 合格证据标准
- `priority`: `P0` / `P1` / `P2`
- `status`: 当前分类计划状态
- `script_path`: 未来脚本目录
- `ledger_link`: 该分类回落到的具体台账
- `matched_module_count`: 当前已映射模块数
- `matched_modules`: 当前已映射模块列表
- `matched_file_count`: 当前已映射文件数
- `matched_file_examples`: 当前已映射文件示例
- `matched_function_count`: 当前已映射函数或场景数
- `notes`: 补充说明

## 与函数级台账的关系

现在 Agent 的三个主台账已经全部带有：

- `category_id`
- `category_name`

执行时的约束是：

1. 每个 Agent 相关函数，必须先落入一个 Agent 分类。
2. 每个 Agent 场景，必须能沿着 `category_id` 回到一个分类总账。
3. 分类总账里的文件数和函数数，必须能在具体台账中反查得到。
