# Agent 代码事实基线

更新日期：2026-08-28。本文件只记录从当前源码 `Code/backend/src/main/java`、配置与迁移文件**核准**的事实，作为测试规划与验收的锚点。标“待实测”的项目表示代码存在但需要真实服务验证。

## 一、入口与调用链

### 1.1 非流式 `POST /v2/agent/chat`
表示 [V2AgentAiService.java](../../Code/backend/src/main/java/com/zhihuiji/backend/application/service/v2/V2AgentAiService.java) `chat()`：

```text
认证(currentOwnerService) → normalizeRequired(message)
→ resolveImageInputs(≤9 张，仅 image/*，当前 owner)
→ resolveConversation（显式 conversation_id 或新建，标题=消息前 24 字）
→ 生成 runId(UUID) → 落 user 消息 → createRunAudit → registerRun
→ (非流式也发 run_started 到 null emitter，仅审计) → SafetyGuard.evaluateSafety
→ 被 block 时：落 blocked assistant 消息 + finishRunAudit(blocked) + 结构化作答
→ ContextBuilder.build(owner, conv, message, toolCatalog, scopeDescriptionWithMemory)
→ ContextCompactionService.compactIfNeeded
→ buildResponse：ToolPlanner.planTools → AgentIterationPolicy.budgetFor → AgentRunState
  → executeToolPlan（ToolExecutor.execute：范围门→参数门→权限/上下文门→执行）
  → recordTranscriptRound（call_id 配对，缺结果记 missing_output）
  → emitDraftCreatedEvents → ReAct while 循环（planNextIteration 各路径）
  → resolveRunOutcome（COMPLETED / CONFIRMATION_PENDING / EXHAUSTED）
→ AnswerSynthesizer.buildFinalAnswer → applyTerminalAnswerSuffix（状态后缀）
→ isLlmFailure 判定 → 落 assistant 消息 → extractMemoriesAfterAnswer（异步）
→ finishRunAudit → AgentChatResponse（含 terminal_status/error_code/safe_message/completed_tools/missing_target_tools）
```

### 1.2 流式 `POST /v2/agent/chat/stream`
`chatStream()` + `runChatStream()`：虚拟线程执行；`SseEmitter` 超时 180s；`SecurityContext` 捕获并在工作线程恢复。取消抛 `AgentRunCancelledException` 收敛，cancelled 时不被 `STREAM_ERROR` 覆盖。

### 1.3 取消与审计
`cancelRun(runId)`：只允许 run owner 取消；`run_cancelled` → 落 cancelled 终态消息 → `finishRunAudit(cancelled)`。
`getRunAudit(runId)`：`awaitRunAuditEvents` 后按 owner 读取审计与事件（seq 升序）。

### 2.5 特殊执行约束（代码内联，测试必须覆盖）

- `result_visualization`：首轮不展示；仅当已有真实只读查询结果（`query_audit.returned_count>0`）且未被跳过时才允许；无真实 facts 时 `tool_skipped(visualization_requires_new_real_facts)`；mode 限定 `auto/table/chart/kpi/timeline`。
- 同一工具相同语义参数只执行一次：`duplicate_tool_semantic_key` 跳过（`ToolInvocationIdentity.key`）。
- 单 run 工具调用预算：`MAX_TOOL_CALLS_PER_RUN = 12`，超出 `run_tool_budget_exhausted` 跳过。
- 模型原始参数非法 JSON：结构化失败 `TOOL_ARGUMENTS_INVALID`，禁止用 `{}` 掩盖。
- 目标写工具检测：`AgentPromptCatalog.targetWriteTool(message)`（关键词含 采购退/销售退/入库/采购/开一单/转账/付款/库存调整/盘点/商品/客户/供应商/收入支出/上传 等）。
- 海报任务：消息含“海报”即登记 `generate_poster_prompt` 为目标工具。
- `create_customer` 参数恢复：`ToolPlanner` 从用户原话只恢复显式 name/phone（正则），不扩展为通用路由。

## 三、执行门与稳定错误码（[ToolExecutor.java](../../Code/backend/src/main/java/com/zhihuiji/backend/application/service/v2/agent/tool/ToolExecutor.java)）

四层：范围门 → 参数门 → 权限与上下文门 → 完成门（CREATE_ONLY 只生成草稿）。

| 错误码 | 触发 | 观察点 |
|---|---|---|
| `TOOL_NOT_REGISTERED` | 未注册工具名 | 不进入业务层 |
| `TOOL_OUT_OF_SCOPE` | 不在本轮允许范围 | 范围门拒绝可有审计 |
| `TOOL_DEPENDENCY_MISSING` | 依赖未完成且必填缺失 | 下一轮先补依赖 |
| `TOOL_ARGUMENTS_INVALID` | 参数 Schema 校验失败 | 业务 Repository 前拒绝 |
| `TOOL_PERMISSION_DENIED` | 真实调用者权限不足 | 按当前认证主体计算 |
| `TOOL_CONTEXT_INVALID` | owner/调用者上下文缺失 | 稳定拒绝 |

`ToolArgumentsValidator` 违反码：`required_missing, type_mismatch, minimum, maximum, exclusive_minimum, exclusive_maximum, min_length, max_length, min_items, max_items, enum, unknown_field, not_object`，携带 `fieldPath`。

## 四、规划器（[ToolPlanner.java](../../Code/backend/src/main/java/com/zhihuiji/backend/application/service/v2/agent/component/ToolPlanner.java)）

- 候选划定：`READ_CANDIDATE_RULES`（44 条关键词规则）、`focusedCandidateToolNamesForMessage`（按写目标推导依赖候选）、`highConfidenceReadCandidates`。语义规则只缩小白名单，实际工具由 Provider `tool_choice=auto` 决定。
- 规划路径优先级：原生 Function Calling（Anthropic Messages `tool_use`）→ JSON 字符串解析（Chat Completions/Responses）→ 单工具澄清轮 `clarifySingleToolSelection`。
- 计划来源 `plan_source` 枚举（实测记录）：`native_tool_use`, `native_tool_use_clarified`, `native_tool_use_react`, `native_tool_use_react_continuation`, `native_tool_use_write_target_retry`, `native_tool_use_single_candidate_retry`, `model_json_plan`, `model_json_plan_react`, `model_terminal_after_tool_results`, `model_tool_selection_failed`, `llm_unavailable`, `llm_planning_failed`。
- 每计划最多 `MAX_TOOLS_PER_PLAN = 6` 个工具。
- ReAct 续轮门（`shouldAllowContinuation`）：单主题已完成查询默认终止；仅显式多来源/展示要求/写目标未完成/海报未完成/依赖补全时继续。
- 多来源识别：`requestsMultipleSources`（放一起/一起看/分别/同时/串起来/对比/比较/都算进去/销售和现金流/库存和补货/客户欠款和供应商应付款）+ 英文 `and/compare/chart`。
- 展示触发：`requestsVisualization`（图表/表格/排行/统计卡/可视化/用图/展示成图等 14 种词）。

## 五、Loop 与终态

### 5.1 轮次与工具预算
| 常量 | 值 | 位置 |
|---|---|---|
| `HARD_ITERATION_CAP` | 6 | AgentRunState |
| `MAX_TOOL_CALLS_PER_RUN` | 12 | V2AgentAiService |
| `MAX_AGENT_ITERATIONS`（旧常量，兼容引用） | 3 | ToolPlanner |
| `MAX_TOOLS_PER_PLAN` | 6 | ToolPlanner |

`AgentIterationPolicy.budgetFor`：纯文本 1 轮；单只读 2 轮；多只读（≥2 工具）3 轮；写目标 4 轮（依赖 ≥2 时 5 轮），均封顶 6。

### 5.2 终态（[AgentTerminalStatus.java](../../Code/backend/src/main/java/com/zhihuiji/backend/application/service/v2/agent/component/AgentTerminalStatus.java)）

| 终态 | SSE 终态事件 | 触发 |
|---|---|---|
| `COMPLETED` | `run_completed` | 只读任务满足完成策略 |
| `CONFIRMATION_PENDING` | `run_completed`（带状态后缀） | CREATE_ONLY 目标已生成草稿 |
| `EXHAUSTED` | `run_exhausted`（含 completed/missing tools） | 写目标未完成且预算耗尽 |
| `FAILED` | `run_failed` / `error` | Provider/工具/回答失败（含 `MODEL_TOOL_SELECTION_FAILED`、`AGENT_ITERATION_EXHAUSTED`、`STREAM_ERROR`、LLM 空回答） |
| `CANCELLED` | `run_cancelled` | 用户取消（经 `cancelRun`） |
| `BLOCKED` | `run_blocked` | SafetyGuard 拦截（`SAFETY_BLOCKED`） |

注意事项：`CONFIRMATION_PENDING`/`EXHAUSTED` 正式回答会追加 `[状态]` 后缀说明，不得表述为已写入；每个 run 只出现一次终态事件。

成功流主线顺序：`run_started → (context_compacted?) → plan_delta → tool_started/tool_completed(可重复) → answer_delta(可重复) → answer_completed → result_block(可重复) → 终态`。创建单工具主线：`run_started → tool_started → tool_completed → draft_created → 终态(CONFIRMATION_PENDING)`。`answer_delta` 由 `AnswerDeltaBatcher` 合并（阈值 24 字符或来源切换）。取消后不得再发回答增量。

结果块类型（`ResultBlockDto.blockType`）：`draft`/`draft_card`（恒展示）、`table`/`rank_list`、`kpi_grid`、`line_chart/area_chart/trend_chart/bar_chart/column_chart/horizontal_bar_chart/pie_chart/timeline`（仅显式展示要求时展示且去重）。

## 七、上下文构建与压缩（ContextBuilder / ContextCompactionService / ContextWindowResolver / TokenEstimator）

### 7.1 预算公式（代码常量）
`usableWindow = min(providerWindow, configuredMaximum=32768)`；未知窗口降级 `providerWindow=8192`（`CONSERVATIVE_FALLBACK_WINDOW`）。比例：system 10%、scope 3%、currentQuestion 8%、toolResult 20%、reservedOutput 15%、safety 10%（降级时额外 +10%），history 为剩余部分。触发压缩：`estimatedInputTokens > historyBudget*70%` 或 `messagesAfterBoundary.size() > 24`。

### 7.2 压缩常量
| 常量 | 值 |
|---|---|
| `COMPACTION_TIMEOUT_MS` | 20000 |
| `DETERMINISTIC_SUMMARY_MAX_LEN` | 1500 |
| `SEMANTIC_SUMMARY_MAX_LEN` | 2500 |
| `MIN_COMPLETED_TURNS_FOR_COMPACTION` | 2 |
| `MIN_COMPACTED_TURNS` | 1 |
| `MAX_CHECKPOINT_REVISION_ATTEMPTS` | 3 |
| `CURRENT_POLICY_VERSION` / `CURRENT_TOOL_SCHEMA_VERSION` | 1 / 1 |

流程：确定性摘要（不调用模型，脱敏手机号/凭据）→ 隔离语义压缩（独立超时、禁工具、JSON 结构校验：字段/字节≤2500/深度≤6/节点≤160/边界 ID 校验）→ 保存检查点（唯一约束冲突回退读已提交，失效重建提升 revision 重试）。压缩后当前请求只使用边界后的原始消息。`invalidateAfterBoundary` 供消息编辑/删除/策略版本变化时失效。

### 7.3 上下文组装顺序（A-G）
A 系统规则 → B owner/store 作用域（含召回记忆，标记历史记忆）→ C 检查点摘要 → D 边界后原始轮次 → E 本轮工具调用/结果 → F 当前用户问题（不可截断）→ G 输出约束与完成策略。

## 九、安全守卫（[SafetyGuard.java](../../Code/backend/src/main/java/com/zhihuiji/backend/application/service/v2/agent/component/SafetyGuard.java)）

1. 规则硬拦截：破坏性 SQL（drop table/delete from/truncate/清空数据库/删除所有数据）、明确越权（别人的/其他账号/越权 + 数据/订单/客户/库存）。
2. 写入安全：破坏性词拒绝；否定写入语义（“不要创建”等）不误判；写入意图检测；金额 >10 万元仅警告；**频率限制 10 分钟 20 条写入**（按 ownerUserId）。
3. LLM 语义审查：命中敏感词（sql/token/密码/管理员/导出/扮演/忽略/ignore previous/system prompt/其他账号 等）时调用模型审查；模型不可用走可审计降级放行。
4. 普通当前账号查询直接放行。

## 十、长期记忆（[AgentMemoryService.java](../../Code/backend/src/main/java/com/zhihuiji/backend/application/service/v2/agent/memory/AgentMemoryService.java)）

- 配置 `agent.memory.*`（`enabled`、召回 limit、maxSummaryLength、maxRecallTextLength 等；默认关闭时召回/提取均跳过）。
- 召回：`recallMemories(owner, store, query, limit)` — DB LIKE 检索，最多 3 条注入上下文并标记“历史记忆（仅供参考）”。
- 提取：回答完成后异步 `extractMemoriesAsync`（确定性规则 Q/A 摘要，conf=0.3，status=active），按 sourceMessageId 去重更新。
- 脱敏：手机号/邮箱/身份证/银行卡/长数字/IP 替换为 `[REDACTED]`；删除/详情/按会话列表接口均存在。
