# Agent 性能测试规划（performance）

更新日期：2026-08-28。性能测试先采集真实样本，再与产品 SLA 或同版本基线比较；无正式 SLA 时建立可复现基线并记 `Deferred`。轮次与工具预算事实见 [../代码事实基线.md](../代码事实基线.md)（轮次硬上限 6、单 run 工具调用预算 12、压缩 20s/摘要上限等）。

## 一、判定通则

- 只使用有效请求作为样本；认证失败、Schema 拒绝、无权限、Provider 不可用、设备缺失单独统计，不混入成功百分位。
- 每个样本记录：样本编号、run_id、owner/store 脱敏标签、工具数、循环轮数、上下文预算字段、工具调用数、SSE 事件数、数据库查询计数、资源采样时间。
- 初始门槛：有效请求 5xx=0；SSE 合法终态唯一；事件丢失/重复按场景规则为 0；创建与确认无重复业务记录；跨 owner/store 串线=0。门槛是起点，不是通过条件。
- 生产 PostgreSQL 不可用时，分页性能只能准备 SQL/脚本，真实 `EXPLAIN` 记 `Blocked`/`Deferred`。

| AG-P-024 | iOS Agent 展示 | 设备具备时每核心流程 10 次 | 首屏、首事件、渲染、内存、断线恢复、重复事件 | 同上；签名/Xcode 缺失记 Blocked |

## 三、指标定义

| 指标 | 起止点 |
|---|---|
| `request_latency_ms` | 发送 → REST 响应结束 |
| `ttfb_ms` | 发送 → 收到响应头/首个 SSE 字节 |
| `first_event_ms` / `first_tool_ms` / `first_answer_ms` | 发送 → 首个合法事件 / `tool_started` / `answer_delta` |
| `completion_ms` | 发送 → 合法终态 |
| `tool_duration_ms` | `tool_started` → `tool_completed/tool_failed`（call_id 配对） |
| `compaction_ms` | 压缩开始 → 检查点可用 |
| `error_rate` / `event_loss_rate` / `duplicate_event_rate` | 按场景、并发级别统计 |
| `memory_delta` | 场景前后 JVM/APP 内存差值 |

## 四、已知基线关注点（来自现行历史问题，涉及性能）

- 32 消息长历史滚动卡顿与内存增长（jank 16.76%、PSS +32MB）此前失败；Soak/长会话用例必须复测并记录。
- 30 轮只读长会话此前在第 16 轮被写入频率限制误拦截；只读长会话必须带否定语义回归（见 security AG-S-027）。
- SSE 取消时序此前出现“取消后 audit 落 failed/STREAM_ERROR”；取消时延用例必须核对 audit 终态为 cancelled。
