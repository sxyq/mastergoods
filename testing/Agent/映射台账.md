## 三、工具 ↔ 类别（60 个全量）

### 3.1 READ_ONLY（46）→ 主 `AG-F-TOOL-RO-*`；交叉 `AG-C-*`（Schema/错误码）、`AG-S-0xx`（越权/注入/注入）、`AG-P-002`（逐工具性能）、`AG-I-*`（真实数据）

覆盖原则：每工具至少执行“有数据非流式、无数据非流式、非法参数、未登录、无权限、跨 owner/store、分页/数量边界、重复请求、有数据流式、无数据流式、清理”11 个分支；各自独立记录，不合并结论。

### 3.2 CREATE_ONLY（14）→ 主 `AG-F-DRAFT-CO-*`；交叉 `AG-D-*`（草稿边界/幂等）、`AG-S-015/016/017`（越确认/重放/幂等冲突）、`AG-P-004/005/014/015`（草稿/确认/竞争）

每工具执行 11 个分支：草稿生成、用户拒绝、用户确认、重复确认、确认失败、非法参数、未登录、无权限、跨 owner/store、并发确认、清理。

## 六、断言链（每条功能用例的统一验收骨架）

```text
APP/HTTP 自然语言输入
  → POST /v2/agent/chat 或 /v2/agent/chat/stream
  → SafetyGuard → ContextBuilder/ContextCompactionService
  → ToolPlanner（计划与允许范围）
  → ToolExecutor：范围门 → 参数门 → 权限与上下文门 → 完成门
  → AgentTool.execute → 当前 owner/store 下的业务 Service/Repository
  → ToolResult/ToolFailureResult → AnswerSynthesizer
  → run-trace/audit + REST 响应或 SSE（run_started…终态）
  → Android/iOS/Web 展示
```
