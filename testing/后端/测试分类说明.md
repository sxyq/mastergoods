# 后端测试分类说明

## 使用原则

后端侧先按测试种类建总账，再按方法和接口填细账。

执行顺序：

1. 先看 `测试分类总台账.csv`
2. 再看 `单元测试` / `功能测试` / `性能测试`
3. 每条方法级、接口级、场景级记录都必须带 `category_id` / `category_name`

## 分类范围

后端测试总账当前覆盖：

- 单元测试 13 类
- 功能测试 11 类
- 性能测试 11 类

其中单元测试新增了两类，用来和真实源码结构对齐：

- `BE-UT-12`：领域实体与聚合约束
- `BE-UT-13`：AI/图像 provider 适配

保留但允许函数计数为 0 的分类：

- `BE-UT-07`：Flyway SQL 校验
  - 原因：这是 SQL 脚本级测试，不进入函数级台账

## 统一台账字段说明

`测试分类总台账.csv` 当前字段：

- `test_type`
- `category_id`
- `category_name`
- `primary_scope`
- `must_cover`
- `evidence_standard`
- `priority`
- `status`
- `script_path`
- `ledger_link`
- `matched_module_count`
- `matched_modules`
- `matched_file_count`
- `matched_file_examples`
- `matched_function_count`
- `notes`

## 与方法级台账的关系

后端的 `unit_function_coverage.csv`、`functional_feature_matrix.csv`、`performance_scope_matrix.csv` 已经全部补上：

- `category_id`
- `category_name`

约束是：

1. 所有 public controller / service / repository 方法先归类。
2. 所有外部接口能力先归到功能测试类。
3. 所有性能热点先归到性能测试类。
4. 总账的模块数、文件数、函数数必须能从具体台账反查得到。
