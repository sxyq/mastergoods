# 智慧记 Web PC 管理端后续开发文档

## 1. 当前目标

Web 端目标是对齐后端真实接口与安卓端业务能力，形成完整 PC 管理界面。PC 端不是营销站，而是面向店长、财务、销售、采购、仓库员工的高密度业务后台。

当前目录归属：

- 后端：`../src/`
- 安卓 UI：`../master-goods-android/`
- Web 前端：`./`
- Stitch 设计资源：`./public/stitch_exports/`

## 2. 已完成基础

- Vue 3 + Vite + TypeScript 项目骨架已经建立。
- 路由、应用布局、登录页、403 页、会话状态和权限守卫已经接入。
- 核心 PC 页面已按业务模块拆分：
  - Dashboard
  - 商品档案、商品编辑
  - 客户/供应商档案
  - 销售列表、新建/编辑、详情、收款、退货
  - 采购列表、新建/编辑、详情、入库、采购退货
  - 付款单详情、资金流水、日常支出
  - 库存流水、库存调整、库存盘点
  - 经营报表
  - AI 助手
  - 角色权限、数据库管理
- API 客户端已经集中在 `src/shared/api/client.ts`。
- 接口契约视图集中在 `src/shared/api/contracts.ts`。
- 前端 RBAC 已覆盖“一个店长（总）+ 多员工角色”的 PC 权限体验。
- 真实账号管理已接入 `/v1/admin/users`，PC 角色绑定暂保存在 Web 本地状态。

## 3. 角色与权限设计

当前 Web 角色：

- `OWNER`：店长（总），唯一超级账号。
- `MANAGER`：店长助理，负责大部分日常业务和员工协同。
- `SALES`：销售员工，负责销售开单、客户、收款查询。
- `PURCHASING`：采购员工，负责采购、供应商、采购收货。
- `WAREHOUSE`：仓库员工，负责库存流水、调整、盘点。
- `FINANCE`：财务员工，负责收付款、资金流水、报表。
- `ASSISTANT`：AI/只读助理，偏查询与辅助。

重要边界：

- Web 现在能按角色控制菜单、页面和按钮。
- 后端仍是 `owner_user_id` 数据域，缺少真实 `store_memberships` / `permissions`。
- 后续要实现跨设备、不可篡改的员工权限，必须补后端成员接口和数据库结构。

## 5. 后续开发路线

### 阶段一：生产级 Web 基础

- 统一页面 loading、empty、error、retry 状态。
- 所有列表补齐分页、排序、服务端筛选。
- 统一表单校验和金额/数量输入规则。
- 统一业务错误提示，细分 401、403、422、500。
- 统一长整型 ID 的字符串化展示与比较。

### 阶段二：核心业务补完

- 商品详情：价格、库存、供应商、历史单价、流水入口。
- 客户详情：销售记录、应收、退货、收款记录。
- 供应商详情：采购记录、应付、退货、付款记录。
- 账户管理：现金、银行、电子账户、余额与启停。
- 付款单列表：状态筛选、批量处理、详情联动。

### 阶段三：数据库与导入工具

- 连接测试：展示数据库类型、地址、延迟、状态。
- 旧库导入：上传/选择旧库，创建任务，查看进度。
- 备份恢复：生成备份、下载备份、恢复前确认。
- 执行日志：按任务展示步骤、耗时、失败原因。

### 阶段四：真实 RBAC 后端化

- 后端新增店铺成员表和角色权限表。
- 当前用户接口返回 store、member、role、permissions。
- Web 登录后不再默认 OWNER，而是按后端权限渲染。
- 角色页改为真实创建成员、改角色、停用、重置密码。
- 安卓端后续同步接入同一权限模型。

### 阶段五：报表与 AI 增强

- 报表拆分为中心页和专题页。
- 支持 CSV 导出、浏览器打印、可见列选择。
- AI 助手增强 result block 展示、审计抽屉、草稿处理。
- AI 工具调用失败时展示可重试操作。

## 6. 开发规范

- 新页面放在 `src/pages/<module>/`。
- 共享 API 类型优先放在 `src/shared/api/client.ts`。
- 业务状态、金额、日期等格式化放在 `src/shared/utils/`。
- 路由入口统一维护在 `src/app/router/routes.ts`。
- Stitch 页面元数据维护在 `src/app/router/stitch-screens.ts`。
- 不新增 UI 框架；保持当前全局 CSS 和业务页面样式体系。
- 涉及图表先用原生 SVG/CSS，除非确实需要第三方库。

## 7. 验收标准

每批 Web 改动至少完成：

- `npm run build` 通过。
- 新增页面可通过路由直接访问。
- API 模式下不会展示本地假数据。
- 无权限角色进入页面会跳转 403 或禁用写操作。
- 表单提交失败要展示后端错误。
- 不提交 `node_modules`、`dist`、本地密钥、构建缓存。

## 8. 当前已知限制

- 本地后端未运行时，真实 API 页面会显示网络错误，这是预期状态。
- 角色权限目前只在 Web 侧完整体验，尚不是后端强鉴权。
- Stitch PC 端现成设计稿只有部分桌面页面，其他页面由移动稿和业务能力升格为 PC 页面。
- 数据库管理页仍是规划型页面，还没有真实执行导入、备份、恢复。
