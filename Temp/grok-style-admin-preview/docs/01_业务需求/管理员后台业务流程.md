## 一、管理员登录流程

```mermaid
sequenceDiagram
    actor A as 管理员
    participant W as 管理后台
    participant S as 管理员认证服务
    participant P as 权限范围服务
    participant L as 审计服务
    A->>W: 提交登录
    W->>S: 发送受保护认证请求
    S->>S: 校验身份与管理员角色
    S->>P: 加载 owner/store 范围
    P-->>S: 返回权限集合与数据范围
    S->>L: 写入登录成功/失败事件
    S-->>W: 会话、角色、菜单权限
    W-->>A: 展示可访问后台
```

验收重点：认证失败不透露账号细节；登录事件含管理员 ID、时间、来源 IP、客户端摘要和结果；前端不能自行声明 `SUPER_ADMIN`。

## 二、数据查看流程

```mermaid
flowchart TD
    A[管理员打开页面] --> B[读取会话身份]
    B --> C{拥有资源读取权限?}
    C -->|否| D[返回403并记录拒绝事件]
    C -->|是| E[解析owner/store范围]
    E --> F[校验筛选条件]
    F --> G[Repository带范围分页查询]
    G --> H[字段脱敏与统计聚合]
    H --> I[返回统一响应]
    I --> J[写入数据访问审计]
```

页面筛选条件是查询意图，不是授权条件。服务端必须先得到管理员可见范围，再把筛选条件与范围合并后查询。

## 三、Agent 运行观测流程

```mermaid
sequenceDiagram
    actor A as 管理员
    participant W as 运行详情页
    participant R as AdminRunQueryService
    participant DB as Agent审计与消息表
    participant X as 脱敏服务
    participant L as 管理员审计
    A->>W: 打开运行记录
    W->>R: runId + 分页参数
    R->>R: 校验admin.agent.run.read与owner/store范围
    R->>DB: 查询运行、会话、消息、事件、检查点
    DB-->>R: 关联数据
    R->>X: 处理正文、参数、结果字段
    X-->>R: 可展示数据
    R-->>W: 基本信息、Token、时间线、终态
    W-->>A: 展示调用链
    R->>L: 记录查看范围与字段级访问
```

页面应把以下顺序明确呈现：请求收到 → 安全判断 → 上下文准备 → 模型计划 → 工具开始 → 工具进度/完成或失败 → 结果判断 → 正式回答 → 运行终态。缺失事件要显示缺失，而不是补写一个看似完整的链路。

## 四、创建类 Agent 任务状态流程

```mermaid
stateDiagram-v2
    [*] --> RUNNING
    RUNNING --> DRAFT_CREATED: 创建类工具完成
    DRAFT_CREATED --> CONFIRMATION_PENDING: 等待用户确认
    CONFIRMATION_PENDING --> REJECTED: 用户拒绝
    CONFIRMATION_PENDING --> CONFIRMED: 用户确认
    CONFIRMED --> WRITTEN: 正式业务写入成功
    CONFIRMED --> WRITE_FAILED: 正式写入失败
    DRAFT_CREATED --> FAILED: 草稿生成失败
    REJECTED --> [*]
    WRITTEN --> [*]
    WRITE_FAILED --> [*]
    FAILED --> [*]
```

管理员后台只读显示状态及证据：草稿内容摘要、确认人、确认时间、正式业务 ID、失败原因和清理结果。它不能通过打开详情、刷新页面或导出操作改变状态。

## 五、高风险配置变更流程

```mermaid
flowchart LR
    A[超级管理员填写模型ID/工具开关] --> B[前端预览影响范围]
    B --> C[二次确认]
    C --> D[服务端校验角色与版本]
    D --> E{校验通过?}
    E -->|否| F[拒绝并审计]
    E -->|是| G[事务写配置]
    G --> H[刷新运行配置]
    H --> I[记录旧值/新值/生效时间]
```

模型 ID 是可管理配置。Provider 密钥及其他认证信息只从受保护配置中读取，后台永不返回。

## 六、审计查询流程

审计观察员查阅审计记录时，会产生新的“查看审计”事件；超级管理员查看、导出或变更配置也会产生相应事件。审计查询结果必须区分：

- 操作成功：目标动作完成。
- 操作失败：服务端拒绝、校验失败或下游错误。
- 访问拒绝：身份存在但没有资源权限。
- 资源不可见：目标不在范围内，不泄露资源存在性。
