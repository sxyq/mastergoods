## 二、功能详细要求

### 2.1 登录与平台总览

| 编号 | 输入 | 处理 | 输出与验收 |
|---|---|---|---|
| BR-F01 | 管理员账号、密码或现有统一登录凭据 | 服务端认证、角色解析、范围加载、会话续期 | 成功进入后台；失败给出通用错误；不暴露账号是否存在；登录时间、IP、客户端摘要写入审计 |
| BR-F02 | 时间范围、owner/store 筛选 | 服务端按权限范围聚合用户、门店、Agent 运行、Token、成功率、延迟 | 指标带统计口径、时间区间和数据更新时间；空数据明确显示 0 或无数据，不使用静态旧值冒充实时结果 |

### 2.2 用户、门店与成员管理

| 编号 | 输入 | 处理 | 输出与验收 |
|---|---|---|---|
| BR-F03 | 用户筛选、状态、角色、owner/store | 查询用户及成员关系；超级管理员可执行停用、恢复、角色调整 | 列表分页稳定；详情展示归属与最近登录；写操作展示影响范围并二次确认；操作前后状态进入审计 |
| BR-F04 | 只读筛选与详情 ID | 按观察员授权范围读取用户、店长、店员和门店关系 | 只能看到授权数据；无写按钮或服务端拒绝写请求；手机号等字段遵循脱敏规则 |
| BR-F05 | 门店信息、owner 关系、成员变更 | 校验 owner/store 关系和成员角色；写入统一业务服务 | 门店数量、活跃状态、店长/店员数可追溯；删除或停用不直接删除业务历史 |

### 2.3 Agent 运行观测

| 编号 | 输入 | 处理 | 输出与验收 |
|---|---|---|---|
| BR-F06 | run ID、用户、owner/store、时间、终态、模型、分页 | 查询运行审计主记录并关联会话、发起者和门店 | 结果包含 run ID、conversation ID、actor、owner/store、开始/结束时间、终态、轮次、工具计数；越权资源不可见 |
| BR-F07 | conversation ID 或 run ID | 分页读取消息，保留角色、消息顺序、运行关联和结构化结果引用 | assistant tool call 与 tool result 可配对；正文按内容权限展示；消息缺失时标明数据不完整 |
| BR-F08 | run ID | 读取 `tool_started`、`tool_progress`、`tool_completed`、`tool_failed` 等事件 | 按事件序列展示工具名、call ID、开始/结束、耗时、状态和脱敏参数；不能把模型计划当作已执行事实 |
| BR-F09 | 时间、模型、owner/store、用户 | 聚合输入 Token、输出 Token、总 Token、请求数、平均和 P95 耗时、首字延迟 | 页面明确 Token 统计来源；对缺少 Provider 用量的记录标记估算；不同模型不可直接混算而不标注 |
| BR-F10 | run ID 或会话 ID | 关联上下文预算、检查点、压缩前后数量和触发原因 | 显示模型窗口上限、输入预算、压缩次数、压缩事件和结果；不展示隐藏推理 |
| BR-F11 | run ID 或 draft ID | 读取草稿状态、确认人、确认时间、正式业务引用和失败原因 | `DRAFT_CREATED`、`CONFIRMATION_PENDING`、`CONFIRMED`、`REJECTED`、`WRITTEN`、`FAILED` 状态边界清楚；观察员不可确认；后台查看不会改变状态 |

### 2.4 Agent 配置与系统管理

| 编号 | 输入 | 处理 | 输出与验收 |
|---|---|---|---|
| BR-F12 | 模型 ID、启用状态、工具开关、适用范围 | 超级管理员提交配置变更；服务端校验格式、范围、并发版本和权限 | 可查看模型 ID 和工具元数据；不能读取 Provider 密钥；变更有审计、版本和生效时间；失败不产生半更新 |
| BR-F14 | 服务、Provider、数据库、SSE、队列状态 | 读取健康检查与近期错误汇总 | 展示服务版本、健康状态、最近检查时间和错误计数；不展示连接密码和完整连接串 |
| BR-F16 | 保留天数、敏感内容策略 | 读取或更新审计、消息、工具结果和统计数据保留策略 | 策略变更需二次确认；清理动作有范围、批次和审计；不可删除正在调查的证据而无授权记录 |

### 2.5 审计与导出

| 编号 | 输入 | 处理 | 输出与验收 |
|---|---|---|---|
| BR-F13 | 管理员、时间、动作、资源、结果、IP | 查询登录、查看、配置、权限和导出事件 | 支持按事件 ID 追踪；记录操作者、时间、IP、User-Agent 摘要、资源范围、结果和失败原因 |
| BR-F15 | 报表类型、字段白名单、时间和范围 | 服务端重新授权，生成脱敏文件或异步任务 | 导出任务有状态和过期时间；不导出凭据；下载和失败均审计；大数据量使用异步分页 |

## 四、功能验收原则

- 页面显示的每个数字都必须能追到统计接口的时间范围、过滤条件和数据更新时间。
- 运行详情必须同时显示“计划工具”“实际工具事件”“正式回答”和“最终状态”，避免只凭 HTTP 200 判断完成。
- 工具调用必须展示 call ID 与结果配对关系；失败、取消、超时和用户拒绝不能被渲染成成功。
- 观察员只能查看；按钮隐藏只是体验措施，接口拒绝和写库为零才是验收条件。
- 原型已实现的静态交互只标记为原型通过，不升级为正式功能通过。
