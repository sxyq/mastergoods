## 二、设计到实现追踪

| 设计主题 | 正式源码目标 | 关键验收 |
|---|---|---|
| 两类管理员 | `infrastructure/security/admin/` | 角色与范围不能由客户端伪造 |
| Agent 运行观测 | `application/service/admin/AdminAgentObservabilityService.java` | run、消息、事件、草稿、检查点可关联 |
| Token 统计 | `infrastructure/repository/admin/AdminUsageQueryRepository.java` | 精确/估算来源清楚 |
| 数据分页 | `infrastructure/repository/admin/` | 数据库分页，不全量读后截取 |
| 模型 ID 管理 | `application/service/admin/AdminConfigService.java` | 密钥字段不存在于 DTO |
| 管理员审计 | `application/service/admin/AdminAuditService.java` | 登录、查看、拒绝和变更均记录 |
| 浅色后台 UI | `pages/admin/`、`features/admin/` | 遵循正式 Web 设计系统和原型语义 |

## 三、证据规则

每个追踪项至少需要：实现文件、测试编号、环境、输入摘要、预期、实际、证据路径和清理动作。没有真实环境或服务时标记 `阻塞`，不以规划文档替代实测结果。
