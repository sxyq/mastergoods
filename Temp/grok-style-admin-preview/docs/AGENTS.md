# 管理员后台规划文档维护规则

## 适用范围

本文件作用于 `Temp/grok-style-admin-preview/docs/` 及其下级目录。它只管理管理员后台规划文档，不替代项目根目录或临时原型根目录中的工程规则。

## 文档范围

- `00_文档总览`：索引、状态、需求追踪和阅读顺序。
- `01_业务需求`：业务目标、角色、数据范围、功能和流程。
- `02_业务系统需求`：系统功能、接口、数据、安全、性能和可观测性要求。
- `03_系统设计`：架构、UI、前端、后端、数据库、接口和权限设计。
- `04_详细设计与实现`：实现目录、执行顺序、迁移、构建和交付说明。
- `05_测试与验收`：功能、安全、性能和集成测试计划与验收条件。
- `06_部署与运维`：环境、部署边界、监控、日志、故障处理和恢复要求。
- `07_问题审计`：问题、风险、审计结论和解除条件。
- `90_历史归档`：只保存已明确标为历史的说明，不参与当前结论。

## 维护规则

1. 文档编号按照 `00 → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 90` 阅读。
2. 需求使用 `BR-ADM`，系统需求使用 `SR-ADM`，接口使用 `API-ADM`，测试用例使用 `TEST-ADM`，问题使用 `ISSUE-ADM`。
3. 每份正式文档保留“文档信息、对应实现、对应接口、对应测试、当前限制”章节。
4. 只记录源码、迁移、原型和测试中能确认的事实；目标设计必须标记为规划中或未完成。
5. 测试结果、问题结果和台账结果只使用 `已完成`、`未完成`、`阻塞`、`延期`；文档生命周期可以使用“规划中”。
6. 变更优先修改原文档和索引，不创建重复备份或第二套目录。
7. 不在本目录编写业务代码、数据库迁移、生产配置或部署脚本。

## 安全规则

- 不读取、粘贴或保存真实密码、Cookie、Session Token、Provider 密钥、私钥和完整认证载荷。
- 可以记录模型 ID、输入/输出/总 Token 数量、耗时和工具名称；这些字段不能与认证凭据混淆。
- 对话正文、工具参数和结果只描述脱敏策略、字段白名单和访问审计，不保存真实内容。
- 不把模型隐藏推理写入文档、页面、SSE 或审计；只记录计划摘要和实际执行事实。
- 不把临时原型的静态数字当成真实用户数、门店数、Token 或运行统计。

## 修改与核验

- 文档编辑使用 `apply_patch`，保持 UTF-8 和 Markdown 结构。
- 修改前检查当前工作树，保留用户已有变更。
- 修改后检查目录索引、编号引用、路径、敏感字段和禁用表达。
- 文档变更不自动触发正式工程构建；若没有运行构建，不能写成构建通过。
