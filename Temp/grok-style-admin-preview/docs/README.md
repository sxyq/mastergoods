## 一、文档用途

这组文档描述仓库管理工具的管理员后台从业务目标到系统设计的完整规划。文档放在临时原型目录内，便于与当前界面一起对照；它不代表正式后台已经接入真实登录、API、数据库或模型服务。

文档顺序固定为：

1. `00_文档总览`：说明阅读顺序、状态口径和需求追踪。
2. `01_业务需求`：说明为什么做、谁使用、管理什么、能查看什么。
3. `02_业务系统需求`：把业务目标转成可验收的系统功能、接口、数据、安全和性能要求。
4. `03_系统设计`：说明页面、前端、后端、数据库、接口和权限如何实现。
5. `04_详细设计与实现`：说明正式工程目录、实现顺序、迁移和构建交付。
6. `05_测试与验收`：说明功能、安全、性能和集成测试如何执行。
7. `06_部署与运维`：说明环境边界、监控、日志和故障处理。
8. `07_问题审计`：记录风险、问题和解除条件。
9. `90_历史归档`：只放历史范围说明，不参与当前结论。

## 五、关键边界

- 管理后台通过受保护的服务端接口读取数据，不能让浏览器直接连接数据库。
- 用户、店长、店员、门店和 Agent 数据必须按照真实调用者的管理员权限计算可见范围。
- 可以管理和展示模型 ID、模型状态及统计信息；Provider 密钥、登录会话凭据、密码、Cookie、私钥和完整认证载荷永不进入页面或日志。
- Token 统计包含输入 Token、输出 Token、总 Token、估算方式和计费状态；它们是用量数据，不是认证凭据。
- 对话正文、工具参数和工具结果属于敏感业务数据。是否展示原文由权限、脱敏策略和访问审计共同决定。
- Agent 的创建类工具应保持“草稿生成—用户确认—正式写入”的业务边界，管理员查看运行过程不能代替最终业务确认。
- 当前文档只规划管理员后台；不改变普通用户端、Android、iOS 或正式业务代码。
